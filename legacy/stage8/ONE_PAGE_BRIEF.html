환급 약속 금고

이미 받은 증빙으로, 약속한 예치금을 직접 청구하는
조건부 환급 시제품

문제와 해결 범위

환급형 교육에서는 조건 충족 다툼과 미지급 피해가 보고된다.[1] 이 시제품은 그중 유효한 증빙과 전액 예치가 이미 확보된 뒤 지급을 실행하는 문제에 집중한다. 미예치·증빙 미발급·학습 사실의 참·예외 분쟁까지 해결하지 않는다.

현재 구현　고정 조건 동의 → 참가자별 50 TEST 예치 → 모의 발급자의 네 서명 → 파일 보관 → 독립 화면·CLI 청구 → 지급 확인

현재 기능 로컬 구현

단일 강좌·고정액, 조건과 수령자에 결합된 증빙 JSON, 서명·기한·준비금 검증, 일회 지급. 수령자와 가스 전달자를 분리한다. 기본 금고·TEST 토큰에는 관리자 동결·조기 회수가 없다.

Solidity · ethers · Node.js · Ganache · 한국어 HTML/JS. 중앙 비교본은 독립 SQLite 원장. 실제 교육 제출 DB는 연결하지 않았다.

AI 융합 계획 / 미검증

원문 약관에서 근거가 붙은 조건 초안과 지원 불가 규정을 제안하고, 사람이 확정하도록 할 계획이다. 폼·규칙·범용 LLM과 비교한 후 채택한다. 현재 AI 호출 경로와 정확도·시간 절감 결과는 없다.

서명 개수·기한 검사는 일반 코드가 담당한다. AI나 체인이 실제 학습 성과를 증명하지 않는다.

기존 대안과 검증할 차이

Accustom의 온체인 담보, Escrow.com의 자동 지급, Stripe의 준비금, Kickback의 자격 확정 후 직접 인출은 이미 선행한다.[3] 검증할 차이는 기관의 사전 서명 파일·전액 고정 준비금·새 지급 승인 없는 집행의 조합이 특정 실행자 위험에 대해 선택 가치가 있는지다. ‘최초’나 시장 우위는 주장하지 않는다.

최초 고객과 재원 가설

구매자는 환급형 소규모 교육업체, 재원은 운영자 sponsor, 발급자는 제출을 확인하는 기관을 가정한다. 운영자가 신뢰 형성을 위해 준비금과 도구 비용을 부담할지는 미확인이다. 현재 가스는 전달자가 부담하며 대납은 없다. 100명×50 TEST=5,000 TEST는 합성 예시다.

판정과 다음 검증

특정 고위험 상황에서만 조건부 지지. 추가 권한은 특정 중앙 지급 실행자가 없어도 조건을 집행하는 경로다. 대가는 지갑·가스·정직한 RPC·신뢰한 화면/명세와 어려운 오류 복구다. 다음은 공개 약관·평가 규약 동결, 이후 실제 AI 비교다. 고객·예치 의향·좁은 장애 수요는 미확인이다.
