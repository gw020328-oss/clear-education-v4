# Isolated self Attestor public rehearsal

This lab follows the official [run-server documentation](https://github.com/reclaimprotocol/attestor-core/blob/bc36dac3657fc46b79b4ecd545262c32440b05a6/docs/run-server.md) using the source commit corresponding to npm attestor-core 5.1.4. It does not change CLEAR's official signer registry, start a product host, reuse user wallets, or automatically replace an unavailable official service.

1. Obtain the official source archive at `source.json`'s fixed `archiveUrl`; verify its `archiveSha256`. Archive mismatch fails closed, even if GitHub repackages the same commit.
2. Install the repository's existing collector and wallet locks with the pinned tools and lifecycle scripts disabled. Apply the reviewed wallet dependency patch as described in `../embedded-wallet/patches/README.md`.
3. Run `./tools/node tools/local-attestor-review/prepare.mjs --archive /absolute/path/to/archive.tgz`. Preparation rejects an existing `var/local-attestor-isolated` directory. Preserve any earlier lab evidence separately before deliberately preparing again.
4. Only for the public example rehearsal, run `./tools/node tools/local-attestor-review/run.mjs --public-example`.

Preparation verifies the archive and collector lock, builds only the official server entrypoint with the pinned esbuild, and makes one reviewed listener change: bind to `127.0.0.1`. Runtime uses an ephemeral port and three fresh, memory-only signer/auth/claim-owner keys in a child with a minimal environment. No inherited credentials, proxies, `.env`, product DB, user session, or user key is loaded. The official source and certificate assets remain under an ignored, private lab directory. Prepared source/build/certificate hashes are rechecked before launch. This is a local test harness, not a hardened deployment or an isolation boundary against a malicious local user.

Authentication is mandatory; its host whitelist is only `example.com`. The rehearsal checks rejection of an unauthenticated connection and a non-allowlisted tunnel. The public HTTPS request has no cookies or authorization header; `secretParams.headers` is an empty object required by the SDK. Server certificate verification stays enabled. There is at most **one claim attempt** (`maxRetries:1` in this SDK counts total attempts), a 90-second worker cap, and a 100-second parent cap. BGP checks are explicitly disabled for this isolated test; no BGP or independent-attestor assurance is claimed. There is no automatic official-service retry or fallback.

The generated claim is verified against the ephemeral local signer. The normal HTTPS official registry is frozen before the request. The real HackerRank verifier is then exercised with synthetic request binding and the local claim and must return `UNTRUSTED_SIGNER` with `paymentAllowed:false`. This checks the signer boundary, not the public example's suitability as a HackerRank proof. Proofs and keys remain in process memory; only fixed booleans/stage names are printed. The process and listener terminate at the end.

2026-10-30 result: authenticated local connection, both rejection checks, public example claim/signature verification, and rejection under the official signer list passed. `officialHostedSuccess=false`, `independentTrust=false`, `productAccepted=false`. No real source account, personal data, paid AI, user signature, transaction, or public deployment was used.
