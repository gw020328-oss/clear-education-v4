## 재사용 자료와 최신 차이

이전 지정 output의 `REVIEW.txt`, `EVALUATION_PLAN.txt`, `GOLDEN_CASES.json`을 다시 확인했다. 31개 사례 명세는 출처/미결/제약을 유지하여 [case-specs.json](../../spikes/ai-vision-preparation/case-specs.json)의 `historical`에 보존했다. 원문 근거 locator·사람 gold·실제 이미지가 준비됐다고 표시하지 않는다.

[후기 사전검토 명세](../current/REVIEW_PRECHECK.ko.md)의 가이드 확보 사실을 반영한다. 이전 문서의 ‘시원스쿨 안내/가이드 미확보’는 현재 전체 가이드 상태로 전용하지 않는다. 반면 실제 폼, BYTE/문자 계산, 문구 위치·키워드 반복·사진 중복·구매시점 적용은 아직 미결이다. 해당 가이드의 기존 상품 hash를 재사용하지 않는다.

현재 우선 시연은 합성 블로그 자료다. 과거 응시 이력 이미지 7종은 보조 회귀로 유지한다. 새 후기·블로그 11종은 7장/무관 사진/판독 불가/링크 누락/정책 충돌/게시 미확인/제목 다양성/계산 미결/부정 후기 대조/캡처 날짜/늦은 revision 응답을 포함한다. 사례의 기대 설명을 정답처럼 모델 prompt에 넣지 않는다.

여러 환급반이 공통 모듈을 사용하는 것이 제품 목표다. 두 브랜드는 초기 검증 프로필이며, 동일 평가·구조화·사전검토 경로가 버전 있는 요구사항을 소비해야 한다. 브랜드별 프롬프트/검사 코드와 임의 실행 코드를 만들지 않는다. 제3 합성 프로필의 지원 규칙 매핑·미지원 질문·프로필 전환 세 가지 명세를 기존 31개와 별도 그룹으로 준비했다. 공통 담당의 제3 프로필·capability 계약 소비는 아직 미실행이다. 400% 사전검토/500% 제외는 현재 시연 프로필 제한이며 일반 엔진의 표현 능력을 브랜드나 환급 숫자로 제한하는 근거가 아니다.

## 검증과 다음 단위

[실행 안내](../../spikes/ai-vision-preparation/README.md)의 명령으로 사례 목록과 평가기의 실패 탐지·실패/지연/취소를 검증한다. 모델 run 수, 도구 self-check 수, 사례 명세 수를 서로 다른 분모로 보고한다. mock 결과는 실제 AI 추출/Vision 정확도·프롬프트 주입 저항 성능이 아니다.

다음 단위는 M1/M2 확정 계약의 소비자 검사다. 이후 근거·질문·운영자 검토와 후기의 확정된 결정적 검사, 관찰 adapter·revision을 단계별로 연결한다. 실제 호출에는 키·승인된 비용 상한·전송/보존 조건이 필요하며 현재 준비 도구는 ACTUAL 실행을 거부한다.

기존 grant/outbox HOLD·독립 청구 제품 NO-GO·원천/Moodle gate, 미확정 예치 정책을 유지한다. OCR 성공은 진위/작성자/전체성이나 지급 승인이 아니다. 공개 게시·URL fetch·실제 개인정보·실제 서류/증명 접근은 이 단위에 없다.
