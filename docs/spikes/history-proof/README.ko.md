# YBM 전체 성적 목록 Reclaim 검증 실험

사용자 요청: 최근 2년 전체 성적 이력을 누락 없이 가져와 증명할 수 있는지 실제 계정으로 검증한다.

## 최신 결과 — 2026-10-14

**실제 계정에서 반환된 성적 표 전체의 Reclaim 공증·독립 검증에 성공했다.** 단일 시험 행을 선택한 증명이 아니라 표 안의 TOEIC 3개 행을 모두 포함한다. 이는 모든 계정의 최근 2년 이력 완전성을 보장하거나 환급 자격을 확정한 결과는 아니다.

| 검사 | 결과 |
|---|---|
| 실제 서버 성적 표 전체 / TOEIC 행 수 | 성공 / 3개 |
| 공식 공증자 서명 / 별도 오프라인 프로세스 검증 | 통과 / 공증자 1개 |
| 요청 URL·추출 정책·진단 owner·nonce·신선도 검증 | 통과 |
| 서명 이후 행 삭제·내용 변경 거부 | 통과 |
| 표 내부 행을 가리는 공격 | 공식 provider 합성 시험에서 거부; 실제 공격 증명 생성은 미시험 |
| 증명 연산 → 서버 검증 요청 | 107초 / 75개 구간 |
| 실제 송신 메시지 | 117,809바이트, 기존 32MiB 상한 유지 |
| 정상 종료·임시 프로필 삭제 | 통과 |
| 제품 DB·환급 자격·체인 지급 연결 | 미실행 |

기존 STWO 전체 표 시도는 약 111MiB 메시지 전송에 실패했다. 공식 SDK의 SnarkJS/Groth16으로 전환하고, 연산을 별도 자식 프로세스로 분리한 뒤 위 실제 계정 검증이 성공했다. 앞선 SnarkJS 연결 종료 원인 자체는 확정하지 않는다.

### CLEAR 적용 판단

등록 시 과거 성적의 기준 증명을 만들고, 수강 후 신규 목표 성적 증명과 구분하는 연동 후보로 채택할 근거가 생겼다. 등록 시점 증명을 나중에 이용하려면 검증 시점·신청 연결·보존 방식이 추가로 필요하다. 이 진단은 원본을 저장하지 않으며 제품용 장기 보존과 공개 체인 제출 형식은 구현하지 않았다.

다음은 미완료다.

- 성적이 없는 계정: 빈 목록을 미응시로 판정하는 실제 원천 검증.
- 기록이 많은 계정: 페이지 분할, 응답 전체 범위, 처리 시간·서버 신선도 제한 검증. 합성 20행 파싱 통과를 실제 다건 공증 성공으로 해석하지 않는다.
- 이번 표 이외의 숨겨진/별도 페이지 기록까지 없다는 보장. 페이지 분할 미탐지는 브라우저 진단이며 표 밖 안내문은 서명 범위가 아니다.
- 수강 신청자와 이력 계정의 동일인 결합, 등록일 기준 기간 경계, 과거 만료 성적 처리.
- 증명 생성 단계의 악의적 선택적 누락을 실제 Attestor에서 검증하는 추가 공격 시험. 서명 이후 행 삭제 거부와 구분한다.
- 개인정보 최소 공개와 제품 통합. 실제 표·성적·수험번호·원본 증명은 공개 체인이나 저장소에 올리지 않는다.

기계 판독용 결과: [verification.json](verification.json). 실제 점수·날짜·수험번호·쿠키·키·원본 증명은 포함하지 않는다.

- 별도 worktree / branch: `codex/history-proof-spike`.
- 기존 단일 시험의 접수·성적 증명과 분리한다. 제품 정책/금고/DB/지급 경로는 변경하지 않는다.
- 실행: `./tools/node src/mac-collector/launch.mjs --ybm-history-check`.
- 기존 Mac 관리형 저장, 공식 Attestor 동일 연결, 독립 오프라인 검증기를 재사용한다.
- 로그인 후 `ready`: 고정된 성적 목록 GET 응답 전체를 메모리에서 수집하고 증명을 생성한다.
- `inspect`: 동일 메모리 증명을 독립 프로세스로 재검사. `retry`: 동일 로그인 연결로 증명 재생성. `close`: 종료·임시 자료 정리.
- 최종 후보는 성적 표 전체를 드러내는 진단이다. 초기 전체 HTML 방식은 전송 크기 문제로 중단했다. 쿠키/응답 Set-Cookie는 가리지만, 성적 표 내부 개인정보는 공증·검증 경로에 포함될 수 있다. 이 형식을 공개 체인에 제출하지 않는다. 최종 제품용 최소 공개/개인정보 보호 증명은 별도 설계다.
- 원본 HTML, 쿠키, 키, 실제 증명은 파일·로그·테스트 fixture에 저장하지 않는다. 사용자별 점수/날짜/수험번호도 결과 보고서에 쓰지 않는다.

## 증명해야 하는 범위

1. 특정 시험 행이 아니라 지정 URL 응답에 포함된 성적 표 전체를 공증받을 수 있는가. 페이지 전체 증명과 구분한다.
2. 서명된 목록의 사후 편집, 다른 추출 규칙, 응답 내부 가림을 탐지/거부하는가.
3. 해당 원천 목록 자체가 요구된 기간과 전체 기록을 포함하는가. 페이지네이션 부재나 `2년` 문구만으로 확정하지 않는다.
4. 수강 신청일 기준 과거 2년과 현재 조회일 기준 과거 2년을 구분한다.

한 계정의 목록 증명 성공을 모든 계정·다른 국내외 시험·만료된 과거 기록·신청자 본인 일치의 성공으로 확장하지 않는다. 빈 목록은 별도 원천 형식 검증 없이 미응시로 승인하지 않는다.

## 진행 기록

- 최초 실제 시도: 응답 수신 후 진단기 문서 검사에서 중단. 증명 생성 전 실패. 임시 프로필 정리.
- 수정: 실제 응답의 HTML 종료 태그 생략을 진단 정보로 다룬다. 빈/로그인 페이지를 미응시로 승인하지 않는다.
- 후속 실제 시도: STWO 전체 표는 116,830,175바이트로 기존 32MiB 송신 상한을 초과했다. 128MiB 실험에서도 전송 실패. 익명 재현에서 큰 메시지는 WebSocket 1009 종료, 작은 STWO 메시지는 서버 invalid proof를 확인했다. 정확한 서버 배포 버전/호환성 원인은 별도 미확정이다.
- 대안: 공식 SDK의 SnarkJS 엔진으로 공개 YBM 페이지 증명 생성 및 공식 서명 검증 성공(115초, 큰 합성 쿠키를 붙인 재시험 134초). 기존 product socket의 32MiB 한도를 그대로 사용한다.
- SnarkJS 실제 계정 전체 표 시험: 3개 성적 행을 읽고 75개 증명 구간 중 71개까지 진행했으나 전송 전 연결 종료(1005). 공식 서명된 실제 이력 증명은 아직 없다. 마지막 진행 로그 사이에 약 43초 간격이 있었으며 원인이 연산 지연인지 다른 연결 장애인지는 미확정이다. 종료 후 관리형 세션 디렉터리 0개를 확인했다.
- 후속 후보: SnarkJS 연산을 메모리 IPC로 연결한 별도 자식 프로세스로 분리한다. SDK의 `web-worker` 의존성이 직접 Node worker_threads 감싸기와 호환되지 않아 프로세스를 사용한다. 합성 AES 증명·변조 거부 성공(18초), 부모 이벤트 루프 최대 지연 3ms. 새 구조의 공개 페이지 공식 서명 검증도 성공했다(113초, 32MiB 한도 유지). 이어 실제 계정 전체 표 검증과 정상 종료·프로필 삭제도 성공했다. 상세 결과는 맨 위 최신 결과를 따른다.
- 익명 40초 연산 비교: 기존 STWO는 타이머가 0회 실행, yield 보완은 69회 실행됐다. 양쪽 모두 연결은 유지됐다. 따라서 event-loop starvation은 확인했지만 연결 종료의 직접 원인으로 확정하지 않는다.
- 합성 시험 59개 통과: 새 이력 전용 시험 19개 및 기존 자격증명/서명/송신 경계 회귀. 자식 프로세스 재사용·취소 종료·오류 비공개 시험을 포함한다. 별도로 SnarkJS 합성 AES 증명·변조 거부 및 공개 페이지 실제 공증을 확인했다. 실제 계정 공증 성공과 구분한다.

## SnarkJS 후보 경계

- 원천 선택, 요청 URL/메서드/공개 헤더, owner/nonce, 공식 공증자 서명 검사는 유지한다. 증명 엔진만 공식 SDK 대안으로 바꾼다.
- `zk-symmetric-crypto@5.1.6`이 고정한 commit `394f777fa404ef184652b6efc5aa60884dd55c7e`의 회로/키를 공식 다운로드 경로로 메모리에 불러온다. branch HEAD를 쓰지 않는다.
- SnarkJS/Groth16과 STWO/STARK의 암호학적 가정은 같지 않다. 엔진 선택 및 trusted setup은 제품 보안 검토에 남긴다.
- 증명용 자식 프로세스는 종료·취소 시 종료를 기다리며, 부모 연결 단절 시 자식도 종료한다. 과거 직접 실행 엔진의 ffjavascript curve/thread cache도 해제한다. 원본 성적/쿠키/증명 저장은 하지 않는다.
- 공개 진단 스크립트만 공개 응답의 제한된 오류 문구를 출력한다. 실제 계정 수집기는 고정된 진단 코드/숫자만 출력한다.

### 연결 종료 가설의 근거와 한계

공개 upstream의 [keep-alive](https://github.com/reclaimprotocol/attestor-core/blob/main/src/server/utils/keep-alive.ts)는 pong/message 수신 시 타이머를 초기화하며, [설정](https://github.com/reclaimprotocol/attestor-core/blob/main/src/config/index.ts)은 무응답 30초 종료다. 이 코드는 실제 배포 지문이 아니며, 이번 1005 종료의 원인을 확정하지 않는다. 프로세스 분리는 연산으로 인한 부모 이벤트 루프 정체를 줄이는 조치이지 네트워크 안정성을 보장하는 조치가 아니다.
