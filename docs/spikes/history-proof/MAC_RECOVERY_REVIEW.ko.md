# PR #32 Mac 복구 검사 재조사 — 2026-10-14

## 결론

**원래 CI 실패 원인은 미확정이다.** 진단과 회귀 시험의 관찰 가능성을 보완했으나,
반복 통과를 원인 수정 완료로 해석하지 않는다. 재조사 당시 권고는 Draft 유지·병합 보류였다.
제품의 자격·지급 차단과 전체 이력 포괄성 관련 제약도 그대로 유지한다.

- [실패한 PR 실행](https://github.com/gw020328-oss/clear-education-v4/actions/runs/38520923338):
  `Mac synthetic recovery`의 44개 중 43개 통과, 1개 실패.

  로그를 놓칠 수 있었다. 따라서 출력에 시작 안내가 없다는 사실만으로 실패 구간을
  확정하지 않는다. `exit`와 `close` 차이가 종료 코드 1의 원인이라는 주장도 하지 않는다.

## 변경

1. worker에 `STALE_RECOVERY`, `SESSION_CREATE`, `BROWSER_CHECK` 단계와 허용 목록의
   오류 코드만 출력한다. 원본 예외 메시지·스택·경로·브라우저 내용은 출력하지 않는다.
2. 시험 결과 수집은 자식의 `close`까지 기다리고 spawn 실패도 거부한다.
3. 강제 종료 후 복구를 독립된 5개 시험으로 반복한다. 실패를 통과할 때까지
   재시도하거나 무시하는 방식이 아니다.
4. 합성 복구 오류 주입으로 허용된 파일 오류만 기록하고 알 수 없는 오류의
   메시지·코드·경로를 노출하지 않는지 검증한다.

브라우저 소유자·프로필 검증, 종료 확인 전 삭제 금지, 실패 시 수집 차단은 변경하지 않았다.
단순 sleep 추가, 예외 무시, 무관한 Chrome 종료, 보안 검사의 완화는 하지 않았다.

## 병합 재검토 기준

원래 오류의 종류를 확보하지 못했으므로 현재 상태를 'Mac 복구 버그 수정 완료'라고
병합 근거에 적을 수 없다. 재발 시 새 단계/고정 코드를 확인하고, 해당 오류를
결정적으로 재현하는 시험을 만든 뒤 수정 전 실패·수정 후 통과를 확인한다.
재조사 당시에는 수정 전까지 Draft 유지를 권고했다. 이후 병합하더라도 그 범위는 격리된
기술 진단이며 모든 계정의 2년 이력 완전성·개인정보 최소 공개·제품 지급 승인과는 별개다.
