## M0.2 추가 공수와 우선순위

승인된 변경은 750점반 50~300% 조건·금액 계산, 400% 조건 구조화·Vision 사전검토다. 원문 대조/실제 미결과 합성 선택은 M0 결정대장에 남긴다. M1/M2는 YBM 수직 경로를 유지하면서 작은 tier/금액 모형과 최초 제출/선택·entitlement binding을 설계한다. X1에서 50/100 출석/100 성적/200/300, 복수 충족·상위 미확인·금액 미정·경계값을 통합한다. V1은 기존 이력 사례를 우선하고 블로그 제출자료 관찰/보완을 별도 profile로 추가한다. 실제 블로그 원천/400% 최종 정산을 임계경로에 넣지 않는다.

상단 M1/M2/V1/X1 추정은 범위 변경을 반영했다. 기존 35~60 인일 대비 추가 **약 4~7 인일**, 총 **39~67 인일**을 재계획용 추정으로 둔다. 공통 작업 겹침·담당 가용시간·새 기준표/모델 평가 난도에 따라 다시 산정하며 실측이나 완료일 약속이 아니다. 공식 선택/공제/가이드 대기와 C0·Windows는 별도다. 기존 A/V 독립 산정·초기 5~9 인일 표기는 변경 전 기록이다.

현재 추가 인수는 M0 예제/명세의 수동 검사이며 제품 기능 인수가 아니다. 조건·계산 지원, 서류 사전검토만, 실제 정책 미확정, 제품 미구현을 UI/인계에서 분리한다. 최종 정산 전 모든 필수 증거·선택·입력·금액 확정 필요; 일부 합성 계산 성공으로 실제 차단을 해제하지 않는다.

## Windows 별도 관문

PR #21 저장 기록에서 Windows 11 STWO 3종·Chrome·기본 OS 진단은 진전됐지만 암호화 확인이 BLOCKED, Job host 강제종료/재시작·PID 재사용·24h 수명·reparse/hardlink 등은 NOT_RUN이다. 긴 경로 bootstrap 실패 후 짧은 경로 성공도 함께 보존한다.

Windows 제품 관문은 일반 사용자 암호화/백업 확인, native handle 기반 저장·ACL, 소유 프로세스 Job tree 종료/복구, 독립 verifier 최소환경/IPC, 패키징/한글·공백/긴 경로, 개인정보 없는 기기 시험이다. gnark/OPRF native는 STWO 성공과 별개다. 기존 평가의 **12~18 인일**은 위 MVP 공수에 포함하지 않으며 전담 가능성과 첫 gate 통과 전 발표 범위에 확정하지 않는다. 플랫폼 보안검사를 삭제하거나 다른 사용자의 브라우저/DB를 정리해 통과시키지 않는다.
