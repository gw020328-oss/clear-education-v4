## 1. 이번에 고정한 범위와 순서

- YBM 750+와 시원스쿨 50~300%의 조건 구조화·고정 → 증거 수집 → 보완 → 자격·금액 판정 → TEST 지급을 최종 시연 목표로 한다. 실제 원천과 합성 판정·재원 조건은 화면/발표에서 구분한다.
- 400% 전용 블로그 챌린지·전용 사전 검토 화면 및 500%는 MVP·발표에서 제외한다. 원문 보관은 그대로 유지하고, 구조화 단계의 원문상 미지원 조건은 OUT_OF_SCOPE로 설명한다. 새 wire enum을 이미 지원한다는 의미는 아니다.

## 2. 제안한 AI 에이전트의 권한과 판정 이력

AI가 원문을 구조화하고 승인된 API 조회·결정적 코드·텍스트/Vision 검사를 조합해 보완·재검증을 관리하는 방향을 설계한다. 임의 URL/계정/도구 실행이나 송금 권한을 주지 않는다. 고정된 도구 목록·인증 주체·호출량/비용 상한·취소/revision 조건을 먼저 정의해야 하며, 이번에 실행 가능한 에이전트를 추가한 것은 아니다.

| 층 | 다루는 것 | 넘겨서는 안 되는 경계 |
| --- | --- | --- |
| 인증된 원천 API/증명 | 해당 원천의 계정·게시·작성 시각·학습·성적 기록 | API 인증만으로 현실 실명·게시물 내용의 진실·전체 이력 완전성을 보장하지 않음 |
| 코드/AI/Vision 관찰 | 분량·필수 항목·내용·판독 불가·조건별 근거 | 관찰 성공을 원천 진위/자격 확정으로 승격하지 않음 |
| 고정 정책 평가 | 경로·기간·공제·반올림·환급액 | AI가 금액·수령인·정책을 임의 변경하지 않음 |
| 지급 계약 | 인증된 판정/증명, 신청·버전·수령인·재원·단회 집행 | 서명 유효성을 AI 해석의 정답이라고 표현하지 않음 |

당사자 열람 자료는 `applicationId`, policy hash/version, subject/account binding revision, evidence ID/revision, source revision, source locator, model/run/profile, facts/selection revision, decision ID와 앞선 decision 참조를 포함하도록 확장한다. 변경 주체·인증 문맥·이유·시각을 남기고 과거 판정을 덮어쓰지 않는다. C3의 기존 snapshot/hash와 revision을 재사용한다. **변경 주체/이유의 완전한 이력과 실제 자료 열람 권한은 아직 없다.**

상세 자료는 권한 있는 학생·학원 당사자에게만 제공하고 원문을 체인에 넣지 않는다. 최소 상태/해시도 개인정보 연결 가능성을 별도로 검토한다. 해시는 변조 대조 수단이며 출처 진위·자료 가용성·실명 확인을 보증하지 않는다. 학원용 조회를 위해 operator에게 모든 학생 조회 권한을 묵시적으로 주지 않는다.

다음은 **설계 후보이며 구현 상수/집행 정책으로 승인된 것이 아니다.** 특히 실패 시 최초 결과 유지안은 멘토 검토 전 지급 코드로 만들지 않는다.

무응답은 증거의 참을 증명하지 않는다. 양측 동의도 담합·탈취·객관적 오류를 없애지 못한다. 모든 기한 뒤에도 인증·서명·원천/신청 결합·재사용 방지 검사는 유지한다. 시간 경과는 거래를 스스로 발생시키지 않으므로 전달자/학생 직접 실행/재시도·체인 확정을 별도로 설계한다.

남은 쟁점: 옛 결과에 대한 동의 재사용, 같은 블록의 동의/이의/정정/지급 경쟁, 수정 후 서명 무효화, 초기 미충족·판단 불가 신청의 구제 비대칭, 자료 열람 불가 중 시간 경과, 재원 부족으로 지급 예정 단계에 못 들어간 신청의 무기한 대기. 상태 명칭·전이·서명 domain/chain/contract·deadline은 아직 wire/ABI로 동결하지 않는다.

고정 검증 서비스의 서명으로 다중 원천 판정을 연결하는 안은 멘토에게 묻는 대안이다. 이를 선택하면 ‘CLEAR 추가 지급 승인 없는 독립 청구’와 보장 수준이 다르다. 72시간 침묵이나 양측 동의만으로 검증 서비스 의존이 사라졌다고 설명하지 않는다.

## 4. 예치 계산 부록의 위치

멘토 질의서의 가정은 100명×20만원=2,000만원, 환급 기준17만원, PG60만원, 여유100만원, 추가충전 여력300만원이다. 400% 인원0/1/2/6을 각 시나리오의300%로 재배분해 총 환급 인원25/40/60/80을 유지했다. 이는 **계산 시나리오의 변경이며 실제 상품의 환급률 전환 규칙이 아니다.**

전달받은 시원스쿨 결과453/711/1,233.5/1,993.5만원, 높은 지급 시 계산상 보관율51.675%를5%p 올림한55%, 초기1,100만원, 높은 지급+여유의 충전233.5만원/극단적993.5만원이다. YBM60%도 기존 가정이다. 본 변경은 산식 재검산이나 실적 확인이 아니며 **코드 상수·보장 예치율로 채택하지 않는다.** 자세한 표는 멘토링 자료를 따른다. 극단 시나리오는 충전 여력300만원을 초과한다.

‘부분/전액 예치 상품 선택+재원 배지’와 ‘PG 자금/온체인 권리의 역할 분리’는 다른 이원화다. PG에 있는 돈을 계약이 실제 지배한다고 주장하지 않는다.

## 6. 이번 실행 결과와 한계

`spikes/decision-trace-readiness/check.mjs`는 저장소에 공개된 `specs/m3/evaluation-http-responses.json`만 읽는다. 별도 DB/API/브라우저·실계정·유료모델을 사용하지 않는다. 기존 digest/schema를 재사용해 다음 연결을 점검한다.

- 신청·정책·수령인·계정 binding, C1 확인 지문, workflow/facts/selection revision.
- snapshot/result 해시, evidence ID/revision/digest, 원천 계정 mapping, rule→evidence revision.
- 과거 결과/current 분리와 SYNTHETIC/HOLD/NO_GO/paymentAllowed=false 유지.

확인한 공개 샘플: 증거4개·규칙4개, workflow8/facts6/selection2. 메타데이터 연결 점검은 성공했지만 **원천 진위·실시간 최신성·접근 권한·변경 주체/이유·완전한 감사 이력은 입증하지 않는다.** 입력과 기대값을 모두 바꿀 수 있는 공격자의 위조를 막는 서명 검증기가 아니다. 출력에는 계정/원문/지갑/증거값을 넣지 않는다. 재계산된 해시만으로 진위를 보증하지 않는다.

재현(고정Node24.21.0, 저장소 의존성 준비 후):

```sh
./tools/node --import ./tests/ybm-collector/network-guard.mjs --test spikes/decision-trace-readiness/inspect.test.mjs
./tools/node --import ./tests/ybm-collector/network-guard.mjs spikes/decision-trace-readiness/check.mjs
```

로컬 검증: 네트워크 연결 차단 상태의 연결/변조·오래된 결과 시험11/11 PASS, 공개 C3 샘플 점검 PASS, `verify:workspace` PASS(원본191개·의존성 그래프 보존), `git diff --check` PASS. CI나 실제 Moodle/공식 YBM 재시험 결과가 아니다. 검토용 worktree의 고정Node/ethers는 기존 설치본을 사용했고 추가 패키지 설치·유료 호출은 없었다.

자금·신뢰 경계 설계의 요청 설정은 Astra/High, 단순 문서·오프라인 점검 구현의 권장 설정은 Sol/Medium이다. 현재 턴의 런타임 모델 변경/ID 독립 확인은 하지 않았다. 멘토 질의서에 적힌 연락처나 개인 파일은 저장소에 복사하거나 발송하지 않았다.
