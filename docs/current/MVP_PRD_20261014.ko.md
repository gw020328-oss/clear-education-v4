## 목적과 사용자

CLEAR는 교육 환급 조건과 계산 방식을 근거와 함께 확정하고, 동의한 정책에 필요한 증거를 검사해 신청별 전액 재원 배정과 단회 청구로 연결하는 모듈이다. 운영자는 AI 초안을 검토·확정하고, 학생은 조건·공제·필요 자료·기한·남는 신뢰를 확인해 동의한다. AI와 Vision에는 정책 게시·자격 확정·지급 승인 권한이 없다.

주 시연은 YBM 750+ 환급코스, 확장은 시원스쿨랩 시작이반 750점반의 50~300% 조건 판정·환급액 계산과 400% 조건 구조화·Vision 서류 사전검토다. 400% 최종 자격·금액 확정·지급은 제외한다. 실제 제휴·학원 내부 시스템 도입을 주장하지 않는다. 2026-11-07 발표 목표는 구현·외부 관문 통과를 전제로 하며 완료 약속이 아니다.

이 표는 제공된 요구자료의 범위 정리다. `750+` 상품명만으로 점수 비교 연산이나 시험 기간을 확정하지 않는다. 모든 수치·기간·서류·공제는 확보 원문과 적용 기수를 확인해 근거 위치를 연결한다. 명확하지 않으면 질문으로 남긴다. 정책 원문에 없는 정상 종료 버튼, 30초 영상, 숨긴 탭 일시정지 등의 실험 조건은 `DEMO_ASSUMPTION`으로 표시하며 공식 규칙과 같은 버전으로 게시하지 않는다.

공식 링크와 확보 지문은 [근거 목록](MVP_GAP_20261014.ko.md#입력-근거와-검증-범위)을 따른다. 초기 통합에서는 첨부 확보 기록을 읽었고, M0에서 공개 로컬 HTML 지문을 대조한 뒤 시원스쿨 공식 표/유의사항을 웹에서 재열람했다. [M0 결정표](M0_DECISIONS.ko.md)는 공식 관찰과 합성 선택·미결을 구분한다. 상세 블로그 가이드는 열람 오류로 미확보이며 원문 AI 추출·실제 모델 호출은 실행하지 않았다. 모든 기수/옵션의 조건 적용을 완전히 검증한 것은 아니다.

Moodle 담당의 10/14 확보본 대조 보고에서 YBM은 90일·매일 새 대상 강의·유효 수강시간 90%·정상 종료일 귀속·모의테스트 1회, 시원스쿨 출석 경로는 100일·다른 대상 강의·진도60%·1.4배속 초과 불인정·OT 포함 조건을 확인했다. 시원스쿨 100% 성적 대안에는 출석을 추가하지 않으며, 200/300%에는 각 tier의 출석 조건을 별도로 적용한다. 이는 정책 초안에 반영할 **출처가 있는 후보값**이며 실제 강의 ID·지표 산식·기간 anchor/종료 의미·공제/후기 기준의 확정이나 기관 API 연결 완료가 아니다. 세부 provenance와 미확정 사항은 [검토 수신 기록](MVP_GAP_20261014.ko.md#역할별-검토-수신-기록)에 있다.

## 정책 확정 흐름

1. 상품·반·기수·확보시각·원문 지문을 고정한다. 공통 조건, 반별 표, 추가 공지의 대상·효력·우선순위를 구분한다. 광고·후기·댓글·개인정보와 모델용 정답표를 입력에서 제외한다.
2. AI는 조건 ID, 원문 위치, AND/OR, 필요한 증거, 시간·금액 식, 누락/충돌/지원 불가와 확인 질문을 반환한다. 모르는 값은 null이다. 문서/이미지 안의 명령은 데이터다.
3. 운영자는 출처별 적용 범위와 질문 답변을 기록한다. 답변이 원문을 바꾸면 공식 조건으로 위장하지 않고 별도 시연 정책 또는 새로운 약정으로 분리한다.
4. 결정적 컴파일러가 타입·단위·기간·분기·증거 충족 가능성·금액 산식·원문 참조를 검사한다. 필수 미확정 항목, 지원하지 않는 검사, 미정 신뢰 권한이 남으면 지급용 게시를 거부한다.
5. 확정 정책·컴파일러/검사기 버전·원천 신뢰 설정·계산식/기한·청구 검증 방식의 지문을 고정한다. 학생에게 조건과 예상액/공제·재원 미확보 가능성을 보여주고 해당 정책에 동의를 받는다. 정책 해시만 저장하고 서버의 다른 규칙으로 지급하는 설계는 허용하지 않는다.
6. 변경은 새 버전/새 신청으로 한다. 이미 동의한 신청에는 소급 적용하지 않는다. 기존 정책·예치·서명·검증 기록의 자동 이관은 이번 MVP에서 하지 않는다.

원문 기반 정책 초안 게시와 지급 실행 가능 여부는 별개다. 예를 들어 과거 전체 이력이 필수인데 검증 수단이 없으면 초안/보류 시연은 가능하지만 해당 경로를 지급 가능으로 게시할 수 없다. 하나의 OR 경로가 미지원이면 그 상태를 숨기거나 삭제하지 않는다. 지원되는 경로만으로 별도 시연하려면 명시적으로 다른 정책 버전을 만들고 차이를 알린다.

## 증거와 보류 원칙

| 증거 | 확인할 사실 | 확인하지 못하는 사실 / 표시 |
| --- | --- | --- |
| Reclaim 성적 | 신뢰한 원천·서명·동일 시험의 점수/일자/종류·owner와 신청/수령인 결합·신선도·재사용 방지 | 단일 성적 존재가 전체 이력·최고점·미응시·실명 인증을 뜻하지 않음 |
| Moodle | 인증된 계정/강좌/활동·고정 기간의 서버 기록, 일별 인정·유효 시간·영상 구간·정상 종료 각각 | 학생 제출 시간을 공식 기록으로 수락하지 않음. LMS 관리자와 원천 기록 신뢰가 남고 사람의 시청/집중도를 증명하지 않음 |
| 제출 파일/Vision | 정책이 요구한 파일 존재, 필드 판독·페이지/좌표 근거, 형식·날짜·값 비교 | 진위, 과거 전체 이력, 동일인, 자격 또는 지급 승인 아님 |
| 모의시험/후기 | 검증 가능한 API·지정 검토 절차의 결과와 근거 | 미연동 항목을 완료로 생성하지 않음. 사람 검토를 쓸 경우 권한·오류/정정 책임을 공개하고 별도 시연 범위로 제한 |

증거 상태는 `MISSING / VERIFYING / VERIFIED / REJECTED / UNVERIFIED`로 구분하고 판독·진위·완전성·결합 검증 상태를 분리한다. 긍정적 존재 조건은 해당 사실의 검증이 필요하며, 최고점/부재/전체 기간 조건은 신뢰한 전체 범위와 누락 없음까지 필요하다. 학생이나 수집기의 `complete=true` 주장은 완전성 근거가 아니다.

필수 증거가 미확인인 선택 경로는 `ON_HOLD`이며 자격·배정·청구로 진행하지 않는다. OR의 다른 경로가 모든 필수 검사를 독립적으로 통과하면 그 경로로 판정할 수 있지만 신청 주체·정책 결합 오류나 해결되지 않은 증거 충돌은 신청 전체를 보류한다. 지원하지 않는 검사를 false 또는 true로 대신하지 않는다.

## Vision MVP

첫 사례는 시원스쿨 성적 경로의 과거 응시 이력 **합성 이미지 사전검토**다. 추가 사례는 400% 블로그 제출자료의 내용 관찰·누락/잘림/불일치·보완 안내이며 원천 게시일·공개 상태·14일 연속·진위/가이드 준수 또는 최종 자격/지급 판정은 아니다. 과거 이력의 전체 성적·계정/이름 화면과 수강 신청일 기준 안내는 [공식 근거 보강](EXAM_HISTORY_REQUIREMENTS.ko.md)에서 확인했다. 정확한 날짜 경계·tier 적용·실제 원천 전체성 및 블로그 상세 가이드는 여전히 미결이다. 기존 M0 시험일/점수 예제는 공식 전체 요건을 충족하는 예제가 아니다. 입력에 `SYNTHETIC DEMO`를 표시하며 실제 수강생 개인정보를 사용하지 않는다.

코드는 파일 미제출을 모델 호출 전에 검사한다. Vision은 정책이 지정한 필드만 값/판독 상태/실제 입력의 페이지·영역 근거로 추출하고, 판독 불가 값은 null로 둔다. 코드는 형식·좌표 범위·날짜·점수·필수 항목·자료 간 불일치를 검사한다. 설명 모델은 검사 사유만 풀어 쓰며 새로운 필수 항목을 만들 수 없다.

`PRECHECK_REQUIREMENTS_MET / NEEDS_SUPPLEMENT / UNDETERMINED`를 표시한다. 정상 판독도 진위/완전성 미확인을 유지한다. 고득점 행이 보이지 않는다는 이유로 최근 2년 고득점 부재 또는 미응시를 확정하지 않는다. V01 정상, V02 미제출, V03 잘림, V04 흐림, V05 일부 기간, V06 이름/날짜 불일치, V07 이미지 내 통과 지시를 평가한다. 모델명·버전·호출 여부·입력 지문·오류·추출 근거·사유와 별도 정답 대비 결과를 남긴다. 모의 응답 통과는 실제 모델 구현/성능 검증이 아니다. 실제 유료 호출은 이번 문서 작업에서 실행하지 않는다.

## 자격·재원·청구

등록은 약정 확정이며 예치를 요구하지 않는 새 구조를 목표로 한다. 자격과 재원 상태를 별도로 저장·표시한다. 자격은 원천의 정정 기간을 거치는 PROVISIONAL과 FINAL을 구분한다. FINAL 자격 충족이어도 전액 배정 전에는 재원 대기다. 배정 뒤 기존 권리를 새 원천 서명·운영자 승인으로 다시 잠그지 않는다. 청구 가능은 검증된 자격, 신청별 전액 배정, 올바른 체인/검증기, 유효 기한, 미지급 상태가 함께 확인된 경우에만 표시한다.

재원은 신청별 전용 계정으로 조달·배정한다는 설계 후보를 사용한다. 부족액은 충전할 수 있지만 일부 지급·20% 고정 비율·공용 부족 재원 선착순 경쟁은 지원하지 않는다. 배정된 전액은 다른 신청에 전용할 수 없다. 학생 청구 후 고정 수령인에게 한 번에 지급한다. 배정도 고정 자격을 확인하는 공개 호출을 목표로 하며 운영자의 추가 선택/승인 단계로 만들지 않는다. 복수 tier에서 자동 max/합산 또는 상위 미확인의 하위 확정을 하지 않는다. 최초 성적/제출 revision·선택 tier·최종 entitlementAmount를 약정/판정/전액 배정에 함께 고정하며 하위 지급 후 차액 자동 추가 지급은 없다. 금액/공제/세금은 확정한 산식과 입력값으로만 계산하며 부동소수점을 사용하지 않는다. ‘약 3%’를 정확한 3%로 채우지 않는다.

취소·회수·기한·재시도·중복 처리의 상태 제안은 [공통 인터페이스](MVP_INTERFACES_20261014.ko.md#재원과-청구의-상태-및-불변식)를 따른다. 학원의 공식 취소/환급 규정이나 법적 약정으로 확정한 값이 아니며, 해당 결정 전 지급용 버전은 freeze할 수 없다.

## 신뢰와 독립 청구

목표는 CLEAR의 임의 추가 지급 승인 없이 고정된 증거 규칙으로 청구하는 것이다. 독립성은 L1 이미 확정/배정된 권리의 서버 없는 청구, L2 서버 없이 새 증거 취득·자격/배정 확정, L3 CLEAR 재량 서명·개인정보 공개 없는 수행으로 나눠 검증한다. L1 합성 성공만으로 L2/L3 제품 성공을 선언하지 않는다. PR #21은 로컬 TLS/OPRF/attestor 확장 실험과 Windows 진단이며 공식 hosted 지원·실제 YBM 적용·독립 제품 청구는 **NO-GO**다. 학습 기록과 기타 서류의 검증 권한도 별도로 해결해야 한다.

정책 해시·오라클 서명만으로 규칙과 실제 검증을 결합했다고 주장하지 않는다. 직접 검증 방식은 체인에서 고정 검증기/정책/결합/중복을 확인해야 한다. 결과 서명 방식은 서명자의 권한·검사 누락 가능성·가용성·오류/폐기 처리 신뢰를 공개해야 하며 독립 청구로 표시하지 않는다.

NO-GO가 계속되면 별도 chain/instance의 합성 TEST 자금 집행 시연과 실제 증거 검증 화면을 분리하는 축소안을 제안한다. 신뢰한 시연 검증자가 있다면 화면에 이를 명시하고 원래 issuer 구조를 최종안으로 확정하지 않는다. 이 대안은 후속 범위 결정 대상이며 현재 grant/outbox 보류를 해제하지 않는다.

체인에 이름·성적·시험일·수험번호·학습 원문·제출파일·개인정보의 추측 가능한 hash를 공개하지 않는다. 필요한 식별 commitment도 연결 가능성과 추측 위험을 검토한다. 선택 경로·주소·금액·nullifier도 연결/추론 위험을 만들 수 있어 OR 만족 사실 등 필요한 최소 정보만 공개하는 방식을 검토한다. 현재 로컬 확장의 attestor는 원문을 보며 자체 CLEAR 운영이면 CLEAR가 원문 수신자가 된다는 신뢰 차이를 숨기지 않는다. 실명 본인인증은 후속이며, 지갑/계정 연결 성공을 실명 인증으로 표현하지 않는다.

## 인수와 제외 범위

첫 통합 인수는 YBM 한 경로의 **명시된 합성 정책·증거·무가치 TEST** end-to-end다. 실제 성적 검증, 짧은 로컬 Moodle 실제 재생, 90/100일 합성 이력, 실제 Vision 호출 결과를 각자 표시한다. 실성적의 점수/날짜를 시연 기간에 맞춰 바꾸지 않는다. 실제 자료가 현재 정책을 충족하지 않으면 보류/미충족으로 끝낸다.

필수 인수: 원문 없는 조건 생성/분기 혼합 차단, 버전 변경 후 기존 약정 불변, 누락/불일치 보류, 미확인 진위/완전성의 허위 통과 0건(정해진 시험집합 기준), 재원 부족→충전→전액 배정, 중복/경쟁/중단 후 단회 지급, 수령인/정책/금액 바꿔치기 거부. 세부 검증과 실제 관문은 [개발 계획](MVP_PLAN_20261014.ko.md)에 있다.

집중도/시선 감시, 모든 문서 자동 진위 보증, 실제 학원 API 제휴, 90/100일 운영 실증, 클릭 없는 송금, 실자금/공개 체인 배포, 기존 예치 자동 이전은 이번 문서 승인 범위에 없다. 실제 Moodle 제품 연동·원천 검증 차단, grant/outbox 보류 및 독립 청구 제품 전환 NO-GO는 유지한다.
