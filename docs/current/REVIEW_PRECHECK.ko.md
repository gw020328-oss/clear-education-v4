# 후기·블로그 챌린지 AI/Vision 사전검토 명세

2026-10-16 최신 범위: [범위·판정 이력·지급 설계 결정 기록](MVP_DECISIONS_20261016.ko.md)을 먼저 읽는다. **400% 전용 기능·시연과500% 제외**, 일반 후기 AI/Vision 검토, 독립 청구 우선이다. 아래400% 사전검토/블로그 주시연 설명은 이전 범위다. 72시간 양측 확인·이의 및 최대120시간 종료는 설계 후보이며, 실패 시 최초 결과 유지·예치 정책은 멘토 검토 대기다. 기존 코드/HTTP/DB/지급 관문을 변경하지 않는다.

2026-10-14, `review-precheck.draft.1`, **DOCS_ONLY / NOT_IMPLEMENTED / CONSUMER_AGREEMENT_PENDING**. 이번 후속은 PRD·명세·계획 갱신이다. 실행 코드·M0 schema/fixture·API·업로드·모델 호출을 변경하지 않는다. YBM 및 시원스쿨 50~300% 기존 범위와 [등록 이력 → 목표 성적 H1](EXAM_LIFECYCLE.ko.md)을 보존한다. 400%는 조건 구조화·제출자료 사전검토만이며 **자동 자격 확정·금액 계산·지급 실행 불가**다. AI 사전검토 결과는 온체인 권한이 아니다.

## 역할과 제안 흐름

공식 규정 입력 → 텍스트 AI가 조건/근거를 구조화 → 누락/충돌 질문 → 운영자 검토·버전 고정 → 본문·이미지·URL 제출 → 결정적 코드 + 텍스트/Vision 항목별 사전검토 → 보완 후 새 revision 재검토를 제안한다.

- 결정적 코드: 확정된 방식의 글자/byte 수, 키워드·태그·링크, 파일/게시물 수. 신뢰한 날짜가 확보된 경우에만 실제 14일 연속성을 판단한다. 합성 날짜 계산 통과는 실제 게시 증명이 아니다.
- 텍스트 AI: 정책 초안·질문, 제목과 본문의 관련성에 대한 구체 근거/인용 위치. 평가 점수로 환급 여부를 결정하지 않는다.
- Vision AI: 학습 자료 유형, 대표사진 유형, 흐림/잘림/손상·판독 가능성. 이미지 수와 내용 적합성은 별도 결과이며 화면의 글자를 읽은 것은 진위 검증이 아니다.
- 외부 원천/학원 연동: 게시 존재·작성자와 신청자 연결·게시/수정 시각·최종 검수까지 공개 유지. 현재 미구현/미검증이며 블로그 Reclaim 검증 성공 기록도 없다. YBM 성적 Reclaim 성공을 블로그·후기 작성폼 검증으로 전용하지 않는다.

YBM은 확인된 요건만 적용한다. **시원스쿨 블로그 챌린지를 AI/Vision의 주 시연**으로 삼고 과거 성적 이미지 예제는 별도 보조/회귀 사례로 유지한다. YBM 주 제품 시연과 H1 성적 이력의 우선순위는 바꾸지 않는다. 실제 사이트 게시 없이 명확히 표시한 합성 자료로 구성한다.

## 결과 데이터 제안과 호환성

아래는 `ReviewRuleCheckDraft`라는 **문서상의 별도 후속 DTO 제안**이며 현재 JSON schema/HTTP 명령에 필드를 추가한 것이 아니다. 소비자 검토 후 버전을 새로 고정한다. 현행 M0의 `additionalProperties:false`, 32개 observation, PNG/JPEG 최대 5장·8MiB/20MP를 몰래 늘리지 않는다. 글당 8장·14개 글을 하나의 기존 DocumentSubmission으로 보내는 방식은 미지원이다. 후속 입력은 글 단위 묶음/14개 manifest와 전체 크기·장수·decode/모델 비용·보존 한도를 먼저 정해야 한다. WORD 언급만으로 DOCX 업로더를 구현하지 않는다.

| 제안 필드 | 기존 계약과 연결 / 의미 |
| --- | --- |
| ruleId, requirementId | 기존 RuleResult.ruleId / DocumentPrecheck.requirementId와 매핑. 금액/자격 RuleResult로 자동 전환하지 않음 |
| policyVersion, policyHash, ruleVersion, applicabilityRef | 기존 binding의 policyVersion/hash 유지, 해석/구매 구간은 별도 versioned reference 제안 |
| sourceReference | Source.sourceId/locator·해당 공지 개정 단락/가이드 절·확보일 참조. 새 hash 미확보는 null, 다른 문서의 hash 재사용 금지 |
| evidenceReference | submissionId/revision·routeRevision·inputHash 및 글/이미지 참조. 본문 위치 또는 기존 FieldObservation.page/bbox 연결; 원문 외부 공개 금지 |
| reviewStatus | 제안 enum `CHECKED / MISSING / NEEDS_REVIEW / UNREADABLE / POLICY_OPEN`. CHECKED는 고정 규칙의 사전검토만 의미 |
| supplementReason, questionId | 보완 사유·근거 위치·정책 질문. 현재 Reason 목록으로 표현 가능한 경우만 매핑하고 새 enum을 구버전에 전송하지 않음 |
| sourceVerificationStatus | 게시 여부/작성자/게시·수정일/공개 유지 각각 UNVERIFIED 기본. 총괄 VERIFIED 하나로 합치지 않음 |
| method, runReference, current | CODE/TEXT_AI/VISION, 기존 ModelRun의 job/run·모델/프롬프트/입력/변환 버전·실행 여부. 늦은 결과는 current=false |
| outcome, paymentAllowed | 기존 DocumentPrecheck outcome과 매핑, paymentAllowed=false. 400% automaticEligibility=false 유지 |

자료 검토의 총괄 표시는 기존 `PRECHECK_REQUIREMENTS_MET / NEEDS_SUPPLEMENT / UNDETERMINED`를 사용한다. 모든 확정 필수 자료 조건이 사전검토에서 확인되면 자료 검토 완료로 표시할 수 있지만 게시 원천은 별도 UNVERIFIED다. 정책 미결/모델 오류/판독불가/주관적 적합성 불명은 UNDETERMINED 또는 항목별 확인 필요다. 확정된 필수 자료 누락은 NEEDS_SUPPLEMENT다. 동시에 여러 사유가 있으면 숨기지 않는다.

현재 `ChallengePrecheck`는 guideStatus=UNAVAILABLE와 제한된 outcome을 가진 **과거 실패/보류 fixture**다. 이번 본문 확보로 이를 현재 원천 상태의 정본으로 삼지 않으며 fixture 자체는 바꾸지 않는다. 확장 결과를 담으려면 별도 계약 버전/소비자 합의가 필요하다. `DocumentPrecheck`의 자료 충족을 `Eligibility.ELIGIBLE`, grant/outbox 또는 400% 지급 권한으로 변환하지 않는다.

## 합성 수용 기준과 평가셋

| 사례 | 기대 항목 결과 / 총괄 표시 | 고정 경계 |
| --- | --- | --- |
| 글당 사진 7장 | 개수 MISSING, NEEDS_SUPPLEMENT | 8장 규칙의 적용 버전이 먼저 고정되어야 함 |
| 8장 중 학습과 무관한 사진 | 개수 CHECKED, 내용 NEEDS_REVIEW | 개수 충족만으로 내용 충족 아님; 자동 자격 불합격 금지 |
| 손상/흐림으로 사진 판독 불가 | UNREADABLE, UNDETERMINED/보완 안내 | 내용 추정 생성 금지 |
| 필수 링크 없음 | MISSING, NEEDS_SUPPLEMENT | URL 자동 탐색/게시 없음 |
| 문구 위치 정책 충돌 | POLICY_OPEN, 운영자 확정 대기 | 상단/하단을 AI가 선택하지 않음 |
| 자료 조건 모두 사전검토 충족, 게시 확인 없음 | PRECHECK_REQUIREMENTS_MET / 게시 미확인 | 400% 최종 자격·지급 불가 |
| 제목 14개에 한 종류의 지정 키워드만 있음 | 집합 다양성 MISSING | 각 글 키워드 존재 통과와 분리 |
| 200byte/800자 계산 방식 미결 | POLICY_OPEN | 임의 인코딩/공백 규칙으로 탈락시키지 않음 |
| 부정적 의견이지만 확정된 형식·증거 동일 | 의견의 긍정/부정만으로 결과 변경 없음 | ‘성의 부족’ 등 새 규칙 금지 |
| 14개 캡처 날짜만 제시 | 날짜 관찰과 원천 미확인 분리 | 실제 연속 게시/공개 유지 자동 확인 금지 |
| 보완 revision 후 이전 모델 응답 도착 | current=false, 최신 결과를 덮지 않음 | 기존 입력/신청/정책/revision 결합 보존 |

평가셋은 위 사례·경계 수량/길이·정책 충돌·구매시점 혼합·본문/이미지 지시문·실패/재시도·부정적 후기 대조쌍을 포함하도록 설계한다. 같은 원본의 파생 이미지/문서를 개발/holdout에 나눠 넣지 않는다. 정답은 정책 버전별 사람 기준표와 근거로 고정하고 ‘확인 필요’도 정답으로 둔다. 규칙별 분모·오탐/누락·근거 없는 판정·보완 정확도·판독불가 보존·주관적 탈락 여부를 구분한다. 현재 실제 평가셋 제작·모델 실행·성능 측정은 하지 않았다.

## 우선순위와 인수

1. R1: 구매시점/정책 적용표·충돌 질문·후속 DTO/입력 한도 확정. 해석과 합성 가정을 분리한다.
2. R2: 확정된 길이/byte·키워드·태그/링크·수량 코드와 실패/경계 검사. 실제 게시 시각 없는 연속성은 보류한다.
3. R3: Vision/텍스트 사전검토·모델/근거/revision·업로드/개인정보·실패/비용 한도. 실제 유료 실행은 별도 승인 필요.
4. R4: 합성 평가셋/개발-holdout·모델 오류/주관적 판정 시험, 화면의 자료/원천 상태 분리.
5. R5: 향후 게시 원천/학원 연동·작성자 결합·공개 유지 검증. 현재 MVP 자료 사전검토의 성공 조건으로 가장하지 않음.

R1~R5는 후속 계획 ID이며 이번 요청이 이 기능들의 구현/실행을 일괄 승인한 것은 아니다. 문서 갱신·기존 계약 회귀와 CI까지만 수행한다. 기존 Moodle·실제 원천 BLOCKED, grant/outbox HOLD, 독립 청구 제품 NO-GO를 유지한다.
