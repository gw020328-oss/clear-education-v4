# CLEAR 모듈 공개와 독립 재현 계획

## 2026-11-02 확정 순서 — 기존 디자인 연결 우선

1. **기존 참가자·운영자 디자인의 신청~증빙/서명/양측 동의~지급 영수증 연결을 먼저 완료한다.** PR138(merge e7f77ed)의 실제100 TEST 지급·블록656·중복 청구 거부·정상 종료 증거는 보존한다. 이 성공을 디자인 전체 연결로 해석하지 않는다. 후속 [PR139](https://github.com/gw020328-oss/clear-education-v4/pull/139)은 기존 디자인 연결의 합성 검증이며, 지금 실제 로그인·유료 AI·지급 재시험을 시작하지 않는다.
2. 이후 김태경 멘토 피드백의 안전장치를 기존 증거와 대조해 **빈 부분만** 검토한다. 수령인/금액 변조, 만료 승인, 이전 판정 버전/결과 해시 불일치, 중복 지급, CLEAR 서버 중단 후 내장 지갑 직접 청구가 대상이다. 서명 후 payload 변조와 서버가 처음부터 잘못된 금액에 유효 서명하는 경우를 구분하고, 후자는 계약 정책/배정에서 차단되는지 확인한다. 직접 청구는 함수 존재 여부가 아니라 이미 온체인 수락·배정된 권리를 별도 경로에서 청구하는 시험 계획으로 정의하며 지갑 접근·RPC·가스 의존성을 명시한다. 로그인·서명을 온체인 권리 확정으로 설명하지 않는다. 서명 불변값과 전진하는 관측값을 구분하고 checkpoint 기능을 확인 없이 제거하지 않으며 현재 버전·예약·지급 상태까지 대조한다. 근거 없이 기존 통과 검사를 반복하지 않는다. 이 작업 단위의 실제 자금·서명·권한 리뷰는 **Astra / High 권장**이며 시작 때 적합 설정을 요청/적용하고 실제 설정을 구분해 기록한다. 현재 UI 구현은 Sol / Medium 기준을 유지한다.
3. 그 뒤 검증 기능의 모듈 입출력·설정·실행·재현 절차를 최소 정리한다. 공개모듈과 다른 PC 독립 재현 목표는 유지한다. 이번 계획 반영만으로 공개배포·대규모 리팩터링·플랫폼 확장을 시작하지 않는다.

**본선 필수 AI 비교 시연은 계획에 병행한다.** 실제 지급 정책과 분리한 사전 설정 환경에서 자연어 조건 구조화→기존 도구 매핑→근거 대조/모호함 보류를 보여준다. 새 사이트 연동 자동생성은 제외한다. 출석률과 콘텐츠 수강률을 무조건 동의어로 처리하거나 면제 조건을 무조건 모순으로 처리하지 않는다. 정상 지급+AI 비교의 발표 합계 약2분을 목표로 한다. 이번에는 계획·의존성만 반영하며 새 병렬 세션이나 실제 호출을 시작하지 않는다.


아래 날짜별 계획·상태는 당시 기록이며 위 확정 순서를 우선한다.

2026-11-01 사용자 확정 목표. 이 문서는 후속 순서와 인수 기준을 기록하며 신규 구현·실제 호출·배포 승인이 아니다. 현재 PRE_SIGN_READ/checkpoint 오류의 최소 수정·회귀시험·최신 CI를 먼저 완료한다. 실제 로그인·지갑 서명·입력별 AI 승인·양측 지급 동의는 기존 본부 조율을 유지한다.

## 사용자 접근과 개발자 연동

- 사용자 접근은 준비된 서비스의 브라우저 화면에서 로그인·검토·서명·결과를 확인하는 경로다. 원격 서비스에 접속할 수 있다는 사실은 그 사용자의 OS에서 로컬 수집기를 실행할 수 있다는 뜻이 아니다.
- 개발자 연동은 문서화한 제품 API와 최소 샘플을 자신의 프론트/서비스에서 사용하는 경로다. 내부 관리·평가·체인 쓰기 API를 전부 공개하지 않는다. 지원 origin, 인증·역할·CSRF, wallet/chain 결합, 요청·오류 DTO, 멱등/UNKNOWN 복구, 기한·재사용 방지 계약을 명시한다.
- 범용 모듈을 목표로 정책/프로필, origin/포트, 체인·계약, 원천 대상과 서비스 위치를 검증된 설정으로 분리한다. 특정 반, 계정, 개발자 Mac 절대 경로를 공용 제품 계약으로 고정하지 않는다. 현재 예제의 고정값은 지원 범위와 함께 예제로 표시한다.

## 최소 패키징과 의존성 공개

우선 버전이 고정된 저장소/릴리스 묶음과 잠금 파일, 준비·검사·실행 명령, API 최소 샘플로 독립 재현이 가능한지 확인한다. 별도 SDK 발행·여러 언어 지원·다중 고객 운영 기능은 선행 조건으로 추가하지 않는다. 재배포 가능한 의존성과 외부 설치 항목을 구분하고 라이선스/배포 조건을 확인한다.

| 항목 | 문서와 인수 시험에서 명시할 내용 |
| --- | --- |
| OS/런타임 | 현재 실제 호스트 기준은 [macOS arm64·고정 Node](BOOTCAMP_NORMAL_HOST.ko.md)다. Linux CI 합성 성공은 다른 OS의 제품 지원 증거가 아니다. Windows 로컬 수집/전체 실행 지원은 미검증으로 표시하고, Windows에서 원격 웹 이용과 로컬 실행을 각각 검증한다 |

의존성 목록은 공개 준비 시 실제 설치 명령과 잠금 파일에 대조한다. 현재 내부 작업본/형제 디렉터리에만 있는 필수 구성은 배포 가능한 소유 소스 또는 설치 절차로 제공하기 전까지 독립 재현 차단 항목으로 기록한다.

## 다른 컴퓨터 인수 절차와 증거

1. 릴리스/커밋, OS·CPU, 브라우저, 런타임과 외부 서비스 버전을 기록하고 빈 작업 경로에서 문서대로 설치한다. 공개 자료에 없는 구두 설명이 필요하면 문서 결함으로 남긴다.
2. 비밀값 없는 샘플로 합성 설치 점검·API 연동을 먼저 수행한다. 실제 서비스/수집 경로는 따로 구분하고 해당 사용자의 계정·키·CA·origin과 격리 환경을 준비한다.
3. 승인된 범위에서 신청부터 지급 결과 조회까지 실행한다. 요청의 공개 식별자·정책/자산 지문·역할·상태·안전 오류 코드·TEST 영수증을 대조하고 중복 요청·만료·재시작 경계를 확인한다.
4. 명령/검사 결과, 화면 단계, 실패와 해결 절차, 외부 지원이 필요했던 부분을 비밀값 제거 후 남긴다. 원문 증명·쿠키·토큰·개인키·회고 본문은 결과 증거로 공개하지 않는다.
5. 합성, 실제 원천, 자체/공식 공증, 로컬 TEST, 공개 테스트넷, 실자산을 별도 결과 칸으로 평가한다. 일부 성공을 전체 제품 완료로 합산하지 않는다.

기존 실행의 코드/자산/증거/승인 기록을 보존하며, 코드 교체를 위한 hotpatch·기한 자동 연장·동의 복사·재사용 방지 완화는 하지 않는다. 현재 오류 수정 적용에는 새 코드 실행이 필요하고 실제 재시험 여부와 사용자 단계는 본부가 조율한다.

작업 모델은 AGENTS 기준으로 선택한다. 서명·권한·자금 경계 검토는 Astra/High를 권장하고, 일반 API/패키징 구현은 Sol/Medium, 단순 문서·상태 갱신은 Sol/Low를 권장한다. 추천과 실제 실행 설정을 구분하며 설정 변경만을 위해 새 세션을 만들지 않는다.
