# 인증된 팀원 제품의 단일 신청·양측 동의 연결

2026-11-02. PR137 병합3a2151f의 실제 시험에서 원천 네 조건 검증, 수령 지갑 등록, REGISTER/ALLOCATE/START_REVIEW까지 진행됐지만 운영자 main 화면이 응답 없는 기수 집계를 기본 COHORT fixture로 대체했다. 실제 단일 신청의 지급 동의가 아닌 예시 명단/확인 버튼이 표시돼 시험을 중단했다. 기존 신청·재원 배정·실패/취소 기록은 보존한다. 지급 완료 근거가 아니며 새 승인/유료 호출을 실행하지 않았다.

## 수정 범위

- 인증된 team entry는 예시 모드가 있는 main dashboard를 import하지 않고, 기존 createTestDriver의 단일 신청 상태를 양측 같은 컴포넌트에 표시한다. 새 controller나 지갑·세션을 만들지 않는다.
- 현재 신청/판정 ID·버전·지문, 정책/매핑 지문, 고정 수령 주소·토큰·100 TEST, 네 조건과 전액 배정, 동의 범위 및 각 역할의 현재 동의를 표시한다. 기수 명단/집계/측정치는 만들지 않는다.
- 기존 driver의 명시적 consent('AGREE')와 gate를 사용한다. 최근 양측 읽기·최초 검토 여유·원래 기한·같은 판정·전액 배정·결과 불명 정책은 유지한다. 현재 decision/procedure/scope의 동의만 완료로 표시한다.
- 동의 응답 불명 시 새 동의 버튼을 표시하지 않고, 사용자가 기존 controller intent의 같은 멱등 키로 수동 확인할 수 있게 한다. 자동 POST/서명/원천/AI 재시도는 없다.
- 조회 중 내부 view가 일시적으로 비워져도 표시한 버튼을 재생성하지 않고 비활성화한다. 최종 실패 시 오래된 판정은 제거한다. 성공한 폴링의 observedAt/카운트다운만 바뀌면 DOM을 유지한다.
- 읽기 전용 v2 operations/v3 procedure의 HTTP409/BC_VIEW_STALE만 transport가 고정 코드로 보존한다. 기존 GET-only reader가 처리하며 POST·다른 경로·다른 오류로 확장하지 않는다.
- 독립 main의 LIVE 운영자 경로도 COHORT fallback을 차단한다. 예시 기수 화면은 비로그인 시연 경로에만 남긴다. 원천·지갑·재원 정책과 backend API 형식은 변경하지 않는다.

## PR138 영수증 조회 CI 후속

영수증 reader는 정확한 내부 RuleError/BC_VIEW_STALE인 경우에만 로컬 권한·신청 projection을 1회 새로 읽는다. canonical receipt 조회 전후의 역할·신청·정책·매핑 재검증을 유지한다. 체인 조회/지급/서명은 반복하지 않는다. 반복 충돌·역행·일반 Error·하위 오류 클래스·권한 철회·다른 신청은 차단한다. 새 재현/거부 시험을 포함한 영수증23/23을 로컬에서 통과했다. V56 원본은 보존하고 기존 영수증 소스 변경만 V57 인수 목록에 추가한다.

## PR138 실행 권한 획득 CI 후속

HEAD `2ea6635`는 영수증 지급 CI를 포함한7개 검사를 통과했지만 E5B의 전송 직전 만료 시험은 의도한 ACCEPT 단계 전에 SETUP/ACQUIRE_RUNTIME에서 `BC_E5_CLOCK_CHANGED`로 중단됐다([실행 기록](https://github.com/gw020328-oss/clear-education-v4/actions/runs/41415096729/job/125177274393)). 이 시점의 키 접근·서명·broadcast는 모두0이었다. 기존 시험의 기대 오류를 넓히거나 실패를 성공으로 처리하지 않는다.

실제 store에서 권한 기록 직후 시각을1초 전진시켜 같은 오류를 재현했다. runtime acquire만 기존 service 최종 검증 루프에 연결한다. fence/lease 기록은1회, 기록된 획득·만료 시각은 원래 값이며 검증만1회 갱신할 수 있다. 매 검증에서 서비스 정체성·원래 권한 만료 하한, runtime 상태·generation, 해당 handle과 원래 lease 만료, 원래 fence 사전 조회의5초 유효 기간을 재확인한다. 반복 충돌·역행·만료·철회·권한 축소·사전 조회 만료는 원자적으로 rollback한다. fence 고갈의 기존 BLOCKED 기록 경로는 유지한다.

새 결정적 시험9개와 기존 강제 종료·경합·이력 회귀를 포함한 실행 검사271/271이 로컬에서 통과했다. 기존 실패한 전송 직전 만료 시험은 그대로 유지하고 실제 격리 체인의 runtime acquire 초 경계 완주 시험을 추가했다. 과거 소스 인수는 보존하고 execution-authority/operations 두 파일의 이번 변경을 V57에 추가한다. 실제 사용자 실행·AI 비용·지급은 시작하지 않았다.

실제 격리 Geth 시계 시험11건에서 지급/만료 차단 조건을 확인했다. 새 acquisition rollover 건은 첫 실행의 지급 단언 통과 후 Docker 연결 단절로 종료 정리가 실패했다. 해당 소유 환경을 정리(영속 상태 보존)하고 Docker 응답 회복 후 이1건만 재검증해 종료까지 통과했다. 나머지10건은 최초 실행에서 통과했다. 소스 호환/변조 차단은196건 통과 후 과거 V8 목록의 편집 실수를 복구하고 해당1건을 다시 통과했다. workspace 보존 검사도 통과했다.
