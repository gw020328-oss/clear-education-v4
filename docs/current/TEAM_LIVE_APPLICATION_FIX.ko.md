# 인증된 팀원 제품의 단일 신청·양측 동의 연결

2026-11-02. PR137 병합3a2151f의 실제 시험에서 원천 네 조건 검증, 수령 지갑 등록, REGISTER/ALLOCATE/START_REVIEW까지 진행됐지만 운영자 main 화면이 응답 없는 기수 집계를 기본 COHORT fixture로 대체했다. 실제 단일 신청의 지급 동의가 아닌 예시 명단/확인 버튼이 표시돼 시험을 중단했다. 기존 신청·재원 배정·실패/취소 기록은 보존한다. 지급 완료 근거가 아니며 새 승인/유료 호출을 실행하지 않았다.

## 수정 범위

- 인증된 team entry는 예시 모드가 있는 main dashboard를 import하지 않고, 기존 createTestDriver의 단일 신청 상태를 양측 같은 컴포넌트에 표시한다. 새 controller나 지갑·세션을 만들지 않는다.
- 현재 신청/판정 ID·버전·지문, 정책/매핑 지문, 고정 수령 주소·토큰·100 TEST, 네 조건과 전액 배정, 동의 범위 및 각 역할의 현재 동의를 표시한다. 기수 명단/집계/측정치는 만들지 않는다.
- 기존 driver의 명시적 consent('AGREE')와 gate를 사용한다. 최근 양측 읽기·최초 검토 여유·원래 기한·같은 판정·전액 배정·결과 불명 정책은 유지한다. 현재 decision/procedure/scope의 동의만 완료로 표시한다.
- 동의 응답 불명 시 새 동의 버튼을 표시하지 않고, 사용자가 기존 controller intent의 같은 멱등 키로 수동 확인할 수 있게 한다. 자동 POST/서명/원천/AI 재시도는 없다.
- 조회 중 내부 view가 일시적으로 비워져도 표시한 버튼을 재생성하지 않고 비활성화한다. 최종 실패 시 오래된 판정은 제거한다. 성공한 폴링의 observedAt/카운트다운만 바뀌면 DOM을 유지한다.
- 읽기 전용 v2 operations/v3 procedure의 HTTP409/BC_VIEW_STALE만 transport가 고정 코드로 보존한다. 기존 GET-only reader가 처리하며 POST·다른 경로·다른 오류로 확장하지 않는다.
- 독립 main의 LIVE 운영자 경로도 COHORT fallback을 차단한다. 예시 기수 화면은 비로그인 시연 경로에만 남긴다. 원천·지갑·재원 정책과 backend API 형식은 변경하지 않는다.

## 검증과 남은 범위

## PR138 영수증 조회 CI 후속
