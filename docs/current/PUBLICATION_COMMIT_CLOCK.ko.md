# 검토 게시의 초 경계 수정과 Attestor 지원 문의

2026-10-29, PR125 후속. 이전 `5842cbb0ac49cd12fc05445f4df2f01554301f43`의 CI 8/9 성공·E5B 실패 기록은 보존한다. 이 문서는 실제 지급 완료 기록이 아니다. 최신 HEAD와 CI 결과는 [PR125](https://github.com/gw020328-oss/clear-education-v4/pull/125)와 [Issue106](https://github.com/gw020328-oss/clear-education-v4/issues/106)에서 확인한다.

## 최소 수정

`publishReview`는 저장 중 시각이 1초 진행되면 기존 `access`의 시작 시각 동등 조건 때문에 `BC_VIEW_STALE`로 취소됐다. `e3-after-command`에서 시각을 1초 전진시키는 결정적 재현으로 확인했다. 원인 재현과 이전 CI 실패를 단독 재실행 성공으로 대체하지 않는다.

실행 코드 수정은 `src/bootcamp/procedure.mjs` 한 파일이다. 기존 동의·준비 명령에서 사용하는 완료 시점 검증을 게시에도 적용한다. 명령과 임시 게시 기록은 한 번만 만들고, 최종 검증 중 시각이 진행하면 읽기 검증만 최대 한 번 반복한다. 두 번째 검사에서도 시각이 진행하면 거부한다. 자동 명령·서명·게시 재실행은 없다.

최종 시각에서 같은 원천 관측과 원래 lease, 원래 검토 상한을 확인한다. 신청 revision/ledger CAS, 자금·체인·등록 port 관측, 서버 역할·세션·운영자 범위를 계속 검증한다. 만료·원천/권한 변경·시계 역행은 저장을 rollback한다. 게시 시각, 120초 확인 시각, 600초 검토 상한, 원천 유효기간을 이동하거나 연장하지 않는다. 새로운 기한·재시도·복구 정책은 추가하지 않는다.

수정 코드 기준은 `faab99be622e0908dfb450f76db18e08b9a97a96`다. v41 인수 기록은 이 변경의 정확한 파일 지문만 승인하며 v1–v40 인수 기록·소비자 원문, 제품 지갑 자산, 기존 권한 경계를 보존한다. 일반 정책/DB/schema/컨트랙트/SDK 잠금/web·PR60은 변경하지 않는다.

외부 네트워크를 차단한 저장소·실행 회귀 792/792, 과거 E5B S3 실패 시나리오 1/1, 정확한 소스 인수 37/37 및 E5/E5B 보존 검사가 통과했다. 새 HEAD CI는 로컬 결과와 구분하여 PR125에 최종 결과를 기록한다. 기존 사용자의 인증 호스트·DB·체인을 재시작하거나 초기화하지 않는다.

## 공식 지원 문의

[공식 문서](https://docs.reclaimprotocol.org/agents/usage)에 안내된 `support@reclaimprotocol.org`와 기존 비공개 지원 대화를 확인했다. 2026-10-29 그 대화에 기술 문의를 발송했다. 이전 답변은 포털 세션 경로에 관한 것이므로 이번 HTTP403의 원인 답변으로 해석하지 않는다. 이번 문의의 답변은 대기 중이다. 공식 문서/공개 상태 자료만으로 현재 차단 정책이나 장애 원인을 확정할 수 없다.

전달한 최소 재현은 공개 `wss://attestor.reclaimprotocol.org:444/ws`, SDK5.1.4/TLS0.1.4/ws8.22.0, 2026-10-29 07:40:40·08:37:36 UTC의 초기 연결 HTTP403 및 `awselb/2.0`/HTML118바이트, 07:46:59 UTC 공개 `/address` GET도403이라는 관측이다. 과거 성공 대비 동일 SDK/잠금·endpoint·초기화 방식·인증 미제공·TLS 설정의 확인 범위와 과거 wire/외부 경로는 같다고 입증하지 못했다는 한계를 명시했다. endpoint 지원 여부, 인증/접근 정책 변경, 해당 시각의 서비스·ALB/WAF 로그 확인을 요청했다.

쿠키·query 실제 값·raw proof·개인 계정·지갑 주소·서명·키·로컬 경로·스크린샷은 전송하지 않았다. 다른 endpoint 전환, IP/헤더 위장, 터널, TLS 검증 해제, 유료 가입 또는 반복 연결 polling은 하지 않는다. 메일 개인 링크와 식별자는 공개 Git에 넣지 않는다.

## 남은 조건

공식 연결 정상 확인 전 새 100 TEST 실제 시험 준비 완료로 표시하지 않는다. Zod3 자원 소모 잔여 위험과 viem peer 버전 불일치의 기존 검토 결론을 유지하며 무차별 major 변경/force audit fix를 섞지 않는다. 새 로그인·유료 AI·증명·사용자 지급 거래는 실행하지 않는다. 운영자 MetaMask의 AI 비용 승인자 지정은 유지하지만 다음 실제 입력에는 별도 직접 승인이 필요하다. 원천·실행·권한·지갑·영수증의 실제 완주는 여전히 미검증이다.
