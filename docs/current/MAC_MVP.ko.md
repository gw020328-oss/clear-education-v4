# Mac 기반 MVP 범위와 보관 정책

11월 7일 목표는 참가자가 자기 PC에서 사용할 수 있는 환급반 제품이다. 현재 Mac으로 개발하고, 첫 수집 도구는 Apple Silicon Mac과 설치된 Chrome을 지원한다. 원본 코드·실험 자료·과거 검증 보고서는 보존한다.

## 승인된 변경

공식 공증자 서명을 검증하는 zkTLS 직접 경로를 MVP 기준으로 사용한다. 추가 TEE 보장은 후속이다. 공증자 신뢰 목록, 원천 추출 규칙, 새 신청과 고정 수취 지갑의 결합, 신선도와 재사용 방지는 여전히 필수다. 기존 TEE 시험의 실패를 성공으로 바꾸거나 서명만으로 전체 자격 검증이 끝났다고 해석하지 않는다.

개인 Chrome 프로필을 재사용하지 않는다. 새 프로필·캐시·임시 파일은 `~/Library/Application Support/CLEAR/collector-v4` 아래 세션별 디렉터리에 둔다. 디렉터리는 사용자 전용 권한을 요구하고 FileVault 활성 상태를 확인하며, 해당 앱 디렉터리만 Time Machine에서 제외한다. 전역 백업·swap·사용자 계정 설정은 변경하지 않는다.

**정상·오류 종료 시 임시 자료를 삭제한다. 실행 중 수집 세션과 원본 보관은 최대 24시간으로 제한한다. 강제 종료·전원 종료로 남은 자료는 다음 실행에서 새 수집을 시작하기 전에 삭제한다.** 앱이 실행되지 않는 동안의 정확한 시각 삭제는 보장하지 않는 예외를 사용자가 승인했다. 삭제는 파일 제거이며 APFS 스냅샷·OS swap·타사 백업 등에서의 복구 불가능성을 뜻하지 않는다. 다른 백업 제품이나 기업 관리 도구가 해당 경로를 복사하는지 사용 기기에서 따로 확인한다.

서버 원본 staging은 우선 메모리 전용으로 구현한다. 신청별 128 KiB, 최대 동시 16개로 제한하고, 발급 성공 또는 오류 종료 시 해당 원본을 해제한다. TTL 상한에서도 해제하며 재시작 후 원본을 복원하지 않는다. SDK 문자열이나 런타임 사본의 보안 소거는 보장하지 않는다. 서비스 보관 청구 자료·최소 검증 이력은 별도 저장소에서 최종 청구 마감 후 30일 이내 삭제하는 기존 정책을 유지한다. 지급 원장과 독립 청구 자료를 세션 청소 대상으로 넣지 않는다.

## 실제 완료 기준

1. 본인 Mac에서 새 YBM 증명을 생성하고 새 신청·수취 지갑에 연결한다. 800점 이상 및 시드 학습 기록 80% 이상을 함께 평가하고 로컬 테스트 금액을 한 번 지급한다.
2. 다른 사용자 최소 1명이 자기 PC와 자기 YBM 계정으로 배포 도구를 사용해 새 증명을 생성한다. 개발자의 쿠키 복사나 사용자별 코드 수정 없이 진행한다. 첫 지원 범위인 Mac 밖의 호환성은 별도로 검증한다.
3. 개발에 참여하지 않은 체험자 최소 2명의 합성 과업 검증을 별도로 진행한다. 실제 YBM 계정 성공과 합성 사용성을 같은 표본으로 세지 않는다.
4. 공개 Amoy와 실제 돈 지급은 필수가 아니다. 로컬 지급·오류 복구·원본 삭제 뒤 독립 청구 완료 증거가 필요하다.

800점 AND 80%, 반 운영기간 내 응시·학습, 인정 시험 최고 총점, 동일 반 동일 시험 중복 지급 차단, 예치 후 지갑 고정, 청구 자료 발급 후 취소·추가 승인 금지, 보완 3일·이후 청구 7일의 기존 결정은 유지한다. 실제 달력 날짜는 첫 동의 전에 확정한다.
