# W02 동일 client 증명 생성·독립 검증 연결

2026-10-12. 추천 GPT-6 Astra / High. PR #3이 병합된 최신 `develop`의 `d880fd65a99109c6802df364fdb40c44d60c0247`에서 `codex/ybm-proof-verification`을 만들었다. 원본 프로젝트·실험·legacy·앞선 브랜치는 보존한다.

## 구현 범위

새 `--ybm-proof-check` 모드는 로그인에 쓰는 공식 Attestor client 객체를 `createClaimOnAttestor`에도 그대로 전달한다. URL이나 새 pool client로 대체하지 않는다. 연결이 끊기면 새 세션이 필요하다. 고정 5.1.4 SDK, STWO 엔진, 한 번의 생성 시도, 증명 동시성 1을 사용한다. TLS 인증서 검증과 기존 응답 가림 정책을 유지한다. [공식 claim 생성 문서](https://github.com/reclaimprotocol/attestor-core/blob/main/docs/claim-creation.md)의 client 전달 경로와 설치된 패키지 구현을 대조했다.

로그인 전에 HTTPS 공식 공증자 registry에서 주소 목록을 읽고 세션의 runtime 지문에 고정한다. 생성 결과의 자체 선언 주소를 신뢰 목록으로 등록하지 않는다. 조회 실패·비정상/과대 응답은 로그인 전에 중단한다. 신뢰 원천은 registry의 HTTPS 응답이며 별도 온체인 registry/TEE 검증을 추가한 것은 아니다.

`ready` 전에는 수집하지 않는다. 이후 성적 목록과 접수 상세의 정확한 URL·메서드·응답 형식을 확인한다. 실제 증명 요청에 필요한 인증 쿠키는 해당 URL에 범위를 제한한 CDP `Network.getCookies`로 조회한다. 전역 쿠키 조회/Network 기록은 켜지 않는다. 접수 POST의 `encExamData`와 빈 `zzxxcc` 형식만 허용하고 인코딩된 값을 그대로 비밀 매개변수로 사용한다. 쿠키와 비밀 POST 값은 메모리에서만 사용하며 로그·파일·검증 프로세스에 전달하지 않는다. 기존 `--ybm-collection-check`에는 이 조회를 추가하지 않는다.

먼저 로컬 HTML로 연결할 성적 행 인덱스를 선택한다. 그 후 고정 원천 정책으로 접수·성적 증명을 순차 생성한다. 원천 HTML/로컬 추출값은 검증기의 기대값으로 보내지 않는다. 각 증명은 같은 사전 승인 owner·신청 결합 hash와 서로 다른 원천 요청 ID를 포함한다. 두 증명 모두 생성되어 독립 검증을 통과한 뒤에만 세션을 완료한다. 부분 성공·만료·취소·연결 단절은 완료로 기록하지 않는다.

## 독립 검증 경계

일회성 Node 자식 프로세스는 네트워크 접근을 차단하고, 개인키·쿠키·원본 HTML 없이 다음 항목을 검증한다. IPC 입력은 128 KiB 이하이며 30초 후 중단한다. 표준 출력/오류를 부모에 전달하지 않고 판정 결과만 반환한 뒤 종료한다.

- 별도로 전달한 신청 기록과 authority/수취 지갑 EIP-712 서명, runtime 지문, 세션 유효기간.
- 고정 공증자 집합에 속하는 주소와 공식 SDK의 claim 서명 검증, identifier 재계산.
- provider, 정확한 전체 params(헤더·URL·메서드·본문 템플릿·추출/가림 포함), 선택한 행 인덱스.
- owner, signed context의 신청 결합·원천 역할·요청 ID·정책 지문, 발급 시각.
- 서명된 추출 필드 schema와 시험 종류·날짜·수험번호의 두 원천 일치.

서명 JSON은 canonical 표기를 요구하여 중복 키·모호한 표기를 거부한다. unsigned 추출 사본과 응답 transcript는 입력에 포함하지 않는다. 공증자가 서명한 claim 검증이며 검증 프로세스에서 전체 TLS/ZK transcript를 재검증하거나 TEE를 추가 검증하는 구조는 아니다. 신뢰할 신청 기록은 현재 메모리의 로컬 진단 authority가 발급한다. 서버 배포·제품 DB·예치·영속 nonce 소비 API는 후속이다.

## 저장·종료

실제 증명·쿠키·키·HTML은 파일로 저장하지 않는다. 결과에는 개인정보 없는 boolean만 남긴다. 정상·오류 종료 때 전용 Chrome 프로필을 삭제하고, 강제 종료 후에는 기존 관리형 복구 정책을 적용한다. JS 문자열/SDK/WASM 메모리의 완전 삭제나 OS 흔적 제거를 보장하지 않는다. SDK의 동기 STWO 연산 중에는 이벤트 루프가 양보할 때 취소 신호를 처리한다. 취소 이후 결과는 받지 않으며 세션을 완료하지 않는다.

기본 실행과 기존 ZIP은 합성 전용이다. 실제 증명 모드는 합성 test root와 함께 실행할 수 없다. 실제 수강료 결제·지급·800점/수강률 자격 판정·목록 완전성·기간 내 최고점·다른 참가자의 실제 운영 검증은 이번 완료 범위가 아니다.

## 실행

`./tools/node src/mac-collector/launch.mjs --ybm-proof-check`로 시작한다. 전용 Chrome에서 사용자 본인이 로그인한 뒤 터미널에 `ready`를 입력한다. 성적 목록을 자동으로 열고, 사용자는 시험접수 → 접수확인/변경/취소(`confirmList.php`) → 해당 시험 접수 상세(`confirmDetail.php`)를 연다. 성적 상세 `scoreDetailToeic.php`는 대상이 아니다. 연결되면 새 증명 생성·독립 검증을 자동 진행하고 종료/프로필 정리 결과를 출력한다. 비밀번호·쿠키·성적표·키를 채팅에 보내지 않는다.

다음 실제 실행·오류 확인에도 추천은 GPT-6 Astra / High다. 병합은 이번 구현 요청의 범위에 포함하지 않는다.

다음 시도를 위해 SDK의 고정 단계명과 오류 종류, 설치된 core 파일의 숫자 행 번호만 출력하도록 보강했다. 오류 메시지/stack 전체는 출력하지 않는다. 진단 비노출 시험 1개 추가 후 수집기 140개, 전체 검증 누계 394개 통과. 첫 구현 커밋의 PR/push CI는 공개 이력·Linux 합성·Mac 복구 모두 통과했다. 최신 수정 CI와 실제 재시도 결과는 후속 기록을 따른다.

## 증명 전송 상한 원인 확인과 수정

`63a1084` 재시도에서 접수 응답·ZK 계산을 마치고 `waiting-for-verification` 단계에 진입한 뒤 `ATTESTOR_BACKPRESSURE_LIMIT`가 발생했다. 서명 증명을 받기 전에 기존 2 MiB 송신 상한이 적용되어 중단된 것이다. 첫 시도의 정확한 원인까지 소급 확정하지 않는다. 종료 후 잔여 session 디렉터리 0개를 다시 확인했다.

일반 중계 모드는 기존 2 MiB/10초 제한을 유지하고, 명시적 증명 모드에만 메시지+대기열 32 MiB/60초 송신 상한을 둔다. 수신 상한은 기존 4 MiB 그대로다. 임의로 무제한 확장하거나 자동 재시도하지 않는다. 초과 시 종료한다. 합성 큰 메시지·대기열 초과·시간 초과·오류 비노출 시험 4개를 추가했다.

고정 SDK의 rpc는 응답 Promise를 먼저 만든 뒤 송신을 기다려, 송신 실패 시 해당 응답 Promise가 미처리 거부로 남을 수 있었다. 현재 client 인스턴스의 응답 대기에 거부 관찰자만 추가했다. 반환하는 원래 Promise와 실제 호출자의 실패 판정은 유지하며, SDK/의존성 파일은 수정하지 않았다. 실제 SDK 인메모리 소켓의 송신 실패→연결 종료 회귀 시험도 통과했다. 수집기 144개, 전체 검증 누계 398개 통과이며 실제 재시도 결과는 별도다.
