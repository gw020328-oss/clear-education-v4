# PR #1 검토 지적 수정과 재현 시험

2026년 10월 11일. 별도 v4 작업본에서 수정했다. 기존 Mac 저장 보고서는 당시 결과로 보존하며, 이 문서는 검토에서 드러난 오류와 이후 수정 범위를 설명한다. 실제 로그인·새 증명·지급·PR 병합은 실행하지 않는다.

## 수정

1. **초기화/Chrome 시작 중 중단**: 종료 신호는 취소를 요청하고 진행 중 작업이 끝난 뒤 한 경로에서 정리한다. 초기화 실패는 부분 생성 폴더를 되돌린다. Chrome 기록 파일 저장 전 실패도 메모리의 자식 프로세스 그룹을 확인해 종료한 후 삭제한다. 종료 확인 실패 때 삭제 완료로 처리하지 않는다. 합성 HTTP 서버도 브라우저 정리 오류와 관계없이 닫는다.
2. **재사용된 PID**: 새 세션은 PID 외에 시작 시각, 부팅 식별자, UID, 명령을 기록한다. 현재 프로세스와 모두 같은 경우에만 활성 세션으로 차단한다. Linux는 `/proc` 시작 tick·boot ID, Mac은 `ps` 시작 시각·부팅 시각을 사용한다. 프로세스 정보 조회 실패는 삭제 허가로 해석하지 않는다. 과거 PID-only 기록은 실행 명령이 worker일 가능성이 있으면 보수적으로 차단하며, 무관한 프로세스는 종료하지 않고 오래된 세션을 정리한다.
3. **새 복제본 패키징**: `.toolchain`의 개발자 전용 LICENSE 의존을 없앴다. 기존 `config/toolchain.json`에 고정된 공식 Node 아카이브와 SHA-256을 사용하고, 그 아카이브에서 실행 파일과 LICENSE를 함께 가져온다. 버전·OS·아키텍처와 출력 준비가 끝나기 전에는 이전 패키지를 교체하지 않는다.
4. **문서 지문**: W01 원본 manifest를 수정하지 않았다. 원본 커밋 `9684b35`와 공개 링크 정리 커밋 `375051e`의 파일을 각 지문으로 검사한다. 공개용 지문은 별도 manifest에 기록하고 기준 커밋과도 대조한다. `verify:workspace`는 브랜치 이름, 로컬 디렉터리 준비, Git에서 보존하지 않는 쓰기 권한 비트에 의존하지 않는다. 로컬 추가 검사는 `verify:workspace:local`로 유지한다.

## 재현과 검증

- 초기화 중 SIGTERM, 초기화 I/O 오류, browser.json 저장 전 SIGTERM, 해당 저장 오류를 주입했다. 각 작업 종료 뒤 지연 확인에서도 세션 폴더가 다시 만들어지지 않았고, Chrome 시험에서는 살아 있는 프로세스 그룹이 없었다.
- 실제 활성 소유자는 계속 차단된다. 같은 PID에 과거 시작 시각/다른 부팅 식별자를 넣으면 정리되고 현재 무관한 프로세스는 계속 살아 있다. 과거 PID-only 처리도 검증했다.
- `.toolchain` 없는 새 복제본에서 공식 런타임을 받아 ZIP 생성, 포함 파일 지문·라이선스 확인, 압축 해제 후 합성 Chrome 실행과 삭제까지 통과했다. 다운로드 실패와 잘못된 아카이브 지문을 주입하면 기존 ZIP 바이트가 유지되고 빌드 임시 폴더가 제거된다.
- 새 복제본의 다른 작업 브랜치와 detached HEAD에서 지문 검사 통과. 원본 manifest, 공개 문서/지문, legacy 변조는 거부한다. 전체 Git 이력이 없으면 명시적 오류로 중단한다.
- Mac 관리형 저장 16개, 시작 중 중단/오류 4개, 브라우저 수명 4개, 패키지 1개, 새 복제본 지문 1개, 공개 이력 검사기 3개: **29개 통과**.
- 기존 ProofAdapter **107개**, 원천/연결/저장 **62개**, 저장 준비 **37개** 통과. 의존성·기존 계약 메모리 컴파일, portable/local workspace 검사 통과. 실제 배포·체인 시작은 하지 않았다.
- 원본 소스 191개, legacy 191개, 원본 문서 4개의 W01 지문 유지. `docs/w01/reference-inputs.json`과 과거 실험 원본은 수정하지 않았다.

## CI와 범위

기존 `Public synthetic tests`에 portable workspace 검사, 새 복제본 변조/이력 시험, 저장 소유자·초기화 회귀를 추가했다. checkout은 전체 이력을 가져온다. 기존 `Public content history`도 유지한다. 필수 검사 이름·승인 조건·관리자 적용을 약화하지 않는다. 새 커밋의 실제 GitHub 실행 링크와 상태는 PR #1 본문/Checks에 기록한다.

Linux CI에서는 Mac Chrome 시작 시험 2개를 명시적으로 건너뛴다. Mac Chrome 수명·패키징은 로컬 Apple Silicon Mac에서 별도로 확인한 결과이며 GitHub Linux에서 검증한 것으로 세지 않는다. Mac 시작 식별자의 시간 해상도는 초 단위이며, 식별이 모호한 legacy worker 기록은 수동 확인이 필요할 수 있다.

이 시험은 합성 자료의 저장/삭제와 패키지 재현성 확인이다. 실제 v4 YBM 수집·신청 결합·지급·타 사용자 실제 수집의 완료 증거가 아니다. 강제 종료/전원 종료 뒤 다음 실행 전 정리 예외도 유지한다.

## 재검토에서 발견한 강제 종료 경계 후속 수정

앞선 정상 취소·오류 처리는 SIGKILL로 복구 코드를 실행할 수 없는 구간을 해결하지 못했다. Chrome 실행 직후 browser.json 저장 전 강제 종료 시, 재실행이 삭제 완료를 표시해도 Chrome의 후속 쓰기로 이전 프로필이 다시 생성되는 사례를 재현했다. 위 최초 시험 통과 기록은 이 시점까지 보장한 것으로 해석하지 않는다.

후속 수정은 시작 대기 프로세스의 기록을 닫은 뒤 Chrome 실행을 허용하고, 부모가 먼저 종료되면 EOF로 Chrome 시작을 막는다. 이미 남아 있는 과거 세션은 기록이 없어도 정확한 프로필 경로로 프로세스를 검색한다. 그룹 전체의 UID·실행 경로·프로필을 확인한 뒤 종료하고, 종료 거부·조회/식별 실패는 삭제 실패로 처리한다. 조회 값이나 프로세스 전체 명령은 로그로 출력하지 않는다.

새 강제 종료 시험 5개는 기록 전·빈 기록·부분 기록·시작 허용 직후·구버전 시작 경로를 검사한다. 구버전 시작 경로는 5회 반복한다. 복구 로직 시험 11개는 다른 사용자/프로필/실행 파일 보호, 그룹 번호 재사용과 종료 거부, 조회 실패를 포함한다. Mac 전체·패키지·지문·검사기 45개와 기존 spike 206개, 총 251개가 로컬에서 통과했다. 원본 지문과 W01 manifest는 변경하지 않는다.

이 후속부터 Mac 실브라우저·패키지 검사를 GitHub `Mac synthetic recovery`에도 추가한다. 앞 절의 ‘Mac 검사는 로컬만’ 설명은 이전 CI 구성이다. Linux의 기존 필수 검사 2개는 유지하며 새 Mac 검사의 실제 실행 결과는 PR #1의 최신 head와 Checks를 기준으로 확인한다.
