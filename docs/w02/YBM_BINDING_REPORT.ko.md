# W02 신청·수취 지갑 결합과 원천 추출 연결

2026-10-11, 최신 `origin/develop`의 PR #2 병합 커밋 `dc08a37e8f37387daf1159a85a2dd6087e8f538f`에서 `codex/ybm-binding-extraction`을 만들었다. 추천 설정은 GPT-6 Astra / High다. 원본 프로젝트, 실험 원본, 기존 작업 브랜치를 보존했다. 사용자는 실제 자산과 분리된 새 로컬 테스트 지갑으로 진단하는 것을 선택했다.

## 구현한 동작

새 `--ybm-collection-check` 모드는 수취 지갑의 EIP-712 서명으로 신청·정책·실행 환경·세션·nonce·임시 owner 공개키·만료 시각을 결합한다. 별도 로컬 authority가 원천 정책과 각 원천의 요청 ID를 포함한 명령에 서명한다. 수집기는 별도로 전달된 신뢰할 신청 기록, authority, 실행 환경과 대조한다. 반환된 envelope 자체를 신뢰할 신청 데이터로 사용하지 않는다. 다른 신청·지갑·owner·명령으로 바꾸거나, 만료·취소·소비된 세션을 재사용하면 거부한다. authority 서명 대기 중 취소되어도 세션이 되살아나지 않는다.

이 authority는 메모리의 **W02 진단용 구성**이다. 세 키는 새로 생성한 로컬 테스트 수취 지갑·임시 owner·명령 서명자이며 디스크나 로그에 기록하지 않는다. `ClearCollectionDiagnostic` 도메인을 사용하고 배포된 vault, 예치, 실제 참가자의 제품 약관 동의가 존재하는 것처럼 만들지 않는다. 제품 신청 API·DB·외부 지갑 연결·복구 정책은 이번 구현의 완료 범위가 아니다. owner 개인키를 Attestor에 보내거나 증명 생성에 사용하지 않는다.

로그인은 기존 공식 Attestor 동일 client 경로에서 진행한다. 로그인 중에는 Fetch/Network 수집이 꺼져 있다. 사용자가 로그인한 뒤 `ready`를 입력해야 아래 두 원천에 한정하여 응답 단계 수집을 켠다.

- `POST https://exam.toeic.co.kr/receipt/confirmDetail.php`: 시험 종류·시험일·수험번호.
- `GET https://exam.toeic.co.kr/result/scoreList.php`: 같은 세 필드와 총점.

실제 URL과 메서드를 다시 검사하므로 쿼리 추가·다른 호스트·잘못된 메서드는 본문을 읽지 않는다. HTTP 200, HTML/UTF-8, 최대 512 KiB를 요구한다. CDP는 상속 파이프이며 메시지 한도 2 MiB를 유지한다. 전용 브라우저의 페이지/팝업은 최대 8개, 대기 이벤트는 최대 32개로 제한한다. CDP 응답 이벤트의 요청 메타데이터에는 인증 헤더 등이 일시적으로 들어올 수 있지만 이를 조회·분석·보관·출력하지 않는다. 쿠키 전체 조회, 로그인 본문 수집, 브라우저 저장소 조회는 하지 않는다.

성적 행은 최대 16개이며 접수 내역의 시험 종류·시험일·수험번호와 일치하는 행을 선택한다. 첫 행이나 가장 큰 숫자를 무조건 선택하지 않는다. 같은 시험의 중복 행·불가능한 날짜·잘못된 점수 단위·두 원천 불일치는 중단한다. 정책에는 모든 허용 행 인덱스의 추출 규칙을 로그인 전에 고정하고, 선택한 행의 별도 요청 ID를 사용한다. 추가 개인정보 필드와 알 수 없는 태그 속성을 허용하지 않는 보수적인 형식이다.

DOM 추출과 공식 HTTP provider의 가림·추출 규칙을 합성 HTTP receipt로 비교했다. SDK의 UTF-8 텍스트 매칭과 바이트 단위 가림 regex를 구분하며 한글 요일 7개도 검사한다. 이름·생년월일·HTML 주석·다른 시험·LC/RC·쿠키·POST 비밀값 canary가 공개 응답에 남지 않는지 검사한다. parse5는 이미 lock에 있던 8.0.1을 직접 의존성으로 고정했으며 기존 전이 의존성 버전은 변경하지 않았다.

## 보장 범위와 한계

**현재 결과는 서명된 수집 명령과 로컬 HTML 형식·연결 진단이다. 실제 YBM 증명의 공식 서명 검증이나 환급 자격 확인이 아니다.** 브라우저 HTML만으로 지급을 허용하지 않는다. 결과에는 시험일·수험번호·총점·지갑·본문 해시를 출력하지 않고 성공 여부만 남긴다. 목록 완전성, 인정 기간 내 최고점, 800점·수강률 80%, 동일 반 시험 중복 지급 여부는 평가하지 않는다.

원천 정책은 `ybm-minimal-candidate.1`, `AWAITING_CURRENT_YBM_LAYOUT` 상태다. 과거 성공 실행기의 URL·필드 구조를 참고했으나 현재 YBM 페이지와 동일하다고 가정하지 않는다. 예상과 다르면 중단하고 검토 후 새 정책 지문과 새 세션으로 재시도해야 한다. 합성 receipt는 TLS 수집이나 공증자 서명이 있는 새 proof가 아니다.

수집 본문 Buffer는 성공·오류 뒤 덮어쓰고 최소 필드도 완료/취소 시 참조를 버린다. JavaScript 문자열·Chrome 캐시·OS 메모리 흔적의 완전 삭제를 보장하지 않는다. 기존 Mac 관리형 저장, 종료 시 프로필 삭제, 강제 종료 후 다음 실행 전 정리 정책을 유지한다. 부분 수집·창 닫기·연결 단절·만료는 완료로 기록하지 않는다.

## 검증

- YBM 수집기 시험 81개: 기존 28개와 신규 53개. 실제 키를 새로 만드는 서명·격리 시험, 합성 추출, SDK receipt, CDP 모의 이벤트 및 실행기 통합을 포함한다. 외부 네트워크는 차단한다.
- Mac/원본 보존/공개 이력 회귀 48개. 실제 Chrome의 로컬 합성 HTTP 응답 읽기·요청 재개 시험 1개를 추가했다. 기존 강제 종료 복구 시험을 유지한다.
- 기존 spike 107 + 62 + 37개. 합계 **335개** 통과.
- `verify:workspace:local`, `verify:dependencies` 통과. 원본·legacy 191개와 기존 성공 실행기 3개의 내용 지문 일치. 원본 문서 지문도 보존했다. 비공개 실험 증명·키·쿠키는 읽거나 복사하지 않았다.
- 실제 로그인 진단과 GitHub CI 상태는 아래 후속 기록으로 구분한다.

## 실행과 다음 연결

`./tools/npm --prefix src/ybm-collector ci --ignore-scripts` 이후 `./tools/node src/mac-collector/launch.mjs --ybm-collection-check`로 실행한다. 전용 Chrome에서 직접 로그인하고 터미널에 `ready`를 입력한 뒤 성적 확인 목록과 선택한 시험의 접수 상세를 연다. 연결 성공 시 자동 종료하며 `close`로 취소할 수 있다. 비밀번호·키·쿠키·성적표를 터미널이나 채팅에 입력하지 않는다. 실제 네트워크 모드는 합성 test root, 기존 합성 ZIP과 섞이지 않는다.

다음 실제 증명 연결의 추천도 **GPT-6 Astra / High**다. 현재 원천 레이아웃을 확인한 다음 같은 Attestor client를 증명 생성 함수에 전달하고, 공식 서명·owner·context·원천 정책·발급 시각을 서버에서 독립적으로 검증해야 한다. 제품 신청/예치 도메인으로의 전환, 실제 인정 기간, 최고점/목록 완전성, 수강률, 중복 차단 및 로컬 지급은 별도 완료 기준이다.
