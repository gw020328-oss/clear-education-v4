# 참가자 화면 UX 정리 — 봉인 파일에 넣을 마운트 한 줄과 필요한 값 (D → 통합 담당)

2026-11-06. 오규원 요청: "봉인 파일은 새 파일로 화면을 구현하고 기존 파일에는 최소 마운트만 추가.
필요한 마운트 위치와 전달받을 상태·콜백을 먼저 알려 달라."

새 화면 코드는 전부 **봉인 안 된 파일**에 있다. 봉인 파일에는 아래 한 줄씩만 들어가면 된다.
시간·동의 가능 여부·인증·지급 판단은 기존 `view`·`conn` 값을 **읽기만** 한다. 새 API·키 없음.

| 새 파일 (봉인 아님) | 내용 |
| --- | --- |
| `web/src/bootcamp/condition-return/stage-strip.js` | 상단 단계 띠 `stageStrip()`, 대시보드용 단계 계산 `participantStage()`, 카드 페이지용 `conditionsLine()` |
| `web/src/bootcamp/condition-return/cards.js` | 네 조건 카드(해야 할 일 → 충족 여부 → 이유·근거 → 다음 행동) · 회고 AI 판단 블록 |
| `web/src/bootcamp/panels.js` (봉인 아님, 기존) | `payoutSummary()` — "100 TEST 지급 완료" 요약. `paymentPanel` 이 안에서 부른다 |
| `web/src/bootcamp/ux.css` | 단계 띠·지급 요약 스타일. `index.html` 이 `styles.css` 다음에 읽는다(이미 추가) |

## 1. 참가자 상단 — 현재 단계와 다음 행동

**마운트 위치**: `web/src/bootcamp/student-view.js` `studentSection()` 의 `render()` 안,
`heroSection(view, …)` **바로 다음** (sessionPanel 앞).

```js
import { stageStrip, participantStage } from './condition-return/stage-strip.js';
// render() 안
heroSection(view, { conn, blocked, onSignIn }),
stageStrip(participantStage({ view, conn, onSignIn })),   // ← 추가 한 줄
```

**전달받는 값**(모두 이미 그 자리에 있음): `view`(decision.conditionsStatus · criteria[].state/label ·
procedure.publishedAt · consent.records/requiredRoles · payment · agreedPayment), `conn`(state, demo), `onSignIn`.

단계 결정(읽기만):
- `conn.state !== 'LIVE'` → 환급 계정 연결 · "로그인하시면 내 기록을 불러와 조건을 확인해요." [로그인]
- `payment.acceptedRight && claimState === 'FINALIZED' && receivedAtoms != null` → 지급 완료 · "내 환급 계정으로 100 TEST를 받았어요."
- `transactionState === 'SUBMITTED' || claimState === 'INCLUDED'` → 양측 확인(지급 처리 중) · "지급 거래를 보냈어요. 블록체인에서 완료를 확인하고 있어요."
- `conditionsStatus === 'MET' && procedure.publishedAt` → 양측 확인 · 참가자 확인만 있으면 "참가자 확인 완료 · 운영자 확인 대기", 둘 다면 "양측 확인 완료 · 지급 처리를 기다려요.", 아직이면 "조건 확인이 끝났어요. 지급 내용과 판단 근거를 확인해 주세요."
- `conditionsStatus === 'MET'`(미공개) → 조건 확인 · "조건 확인이 끝났어요. 환급 재원이 확보되면 양측 확인이 열려요."
- 그 밖 → 조건 확인 · "4개 조건 중 N개를 충족했어요. ○○ 조건을 먼저 채워 주세요."

재확인 접수("다시 확인 요청을 접수했어요…")는 카드 페이지(condition-return)의 tracker 상태에서만 알 수 있어
그쪽 띠가 말한다. 대시보드 `view` 에는 재확인 접수 값이 없다 — **서버 필드 필요**(아래 5절).

## 2. 네 조건 카드 — 해야 할 일 / 충족 여부 / 이유·근거 / 다음 행동

Moodle 탭의 카드(`condition-return/cards.js`)는 이미 새 순서다(봉인 아님).
대시보드 카드(`student-view.js` `progressSection` → `conditionCard(row, …)`, 봉인)도 같은 순서로 바꾸려면:

**마운트 위치**: `progressSection()` 의 `view.criteria.map((row) => conditionCard(row, { onOpen, onToggle }))`
를 새 파일의 렌더러로 교체 — `dashboardConditionCard(row, { onOpen, onToggle, view })` (이름은 통합 담당 선택).
D 가 `condition-return/cards.js` 의 카드 본문을 `view.criteria` 줄 모양으로도 받게 맞춰 둔다(후속).

**전달받는 값**: `row`(criterionId · state · reasonCode · evidenceId · evidenceRevision), `onOpen(criterionId)`,
`onToggle`(라이브 월드만). 근거 세부(Moodle 완료 시각 등)는 대시보드 `view` 에 없으면 접힘 칸을 비운다.

## 3. 회고 검토 — AI 가 무엇을 판단했는지

Moodle 탭 카드에는 이미 들어갔다(확인한 문장 / 부족한 내용 / 서버 판정 사유 / 보완 방법 / [회고 보완하기]).
대시보드의 조건 상세(`student-view.js` `conditionDetail`, 봉인)에 같은 블록을 넣으려면:

**마운트 위치**: `conditionDetail()` 의 회고 분기, 근거 항목(topics) 을 그리는 자리.
```js
import { reflectionReview } from './condition-return/status.js';
import { reflectionBlock } from './condition-return/cards.js';   // export 로 바꿔 둔다
reflectionBlock(reflectionReview({ row, evRow, limitations, phase, aiApproval, sourceText: null }), link)
```
**전달받는 값**: `row`, 근거 줄 `evRow`(checks.topics[{topicId,state,location}], metadataStatus),
`limitations.originalTextHttpAvailable`, 세션 `phase`·`aiApproval`, 회고 게시판 `link`. 원문은 실서버가 주지 않으므로 인용 대신 위치(UTF-16) 표시.

## 4. 지급 완료 — 실제 돈의 이동

`paymentPanel`(봉인 아님) 안에 `payoutSummary()` 가 이미 들어가 있어 **코드 마운트는 필요 없다.**
단, 수령 주소는 `view` 에 없고 `conn.recipient` 에만 있다. 봉인된 `fundingSection()` 의 호출에 인수 하나만 더:

```js
paymentPanel({ view, api, blocked, quiet: true, recipient: conn?.recipient ?? null }),   // ← recipient 추가
```
(`fundingSection(view, { api, blocked })` 에 `conn` 을 넘겨 주는 것도 같이 필요 — `studentSection` 에서 `fundingSection(view, { api, blocked, conn })`.)

"지급 완료" 는 `acceptedRight && claimState === 'FINALIZED' && receivedAtoms != null` 일 때만 쓴다(기존 `isPaid` 와 같음).
서명 완료·거래 전송만으로는 쓰지 않는다. 잔액은 `api.paymentReceipt` 의 `balance` 에 값이 있을 때만 숫자를 적는다.

## 5. 서버 필드 — 없어서 추정하지 않고 비워 둔 것

| 화면 | 필요한 값 | 지금 |
| --- | --- | --- |
| 상단 띠(대시보드) | 재확인 요청 접수 여부·접수 번호 | `view` 에 없음. 카드 페이지의 tracker 만 안다 |
| 지급 완료 | 수령 계정 주소 | `view.payment` 에 없음 → `conn.recipient` 인수로 받기(위 4절) |
| 지급 완료 | 조회된 현재 잔액 | `paymentReceipt.balance.currentAtoms`(또는 `balanceAtoms`) 가 오면 표시. 지금 fixture 엔 없음 → "조회 전" |
| 지급 완료 | 거래 내역 링크(탐색기) | 없음 → 해시 앞뒤·블록 번호만 |
| 지급 처리 중 | "거래를 보냈지만 미확정" 구분 | `transactionState === 'SUBMITTED'` 와 `claimState === 'INCLUDED'` 로 구분 중. 서버가 둘을 따로 주는지 확인 필요 |
| 회고 | 보완 안내 문구 | 서버 reasonCode·topics 만 있음. "보완 방법" 은 부족한 항목 이름으로만 쓰고 판단은 만들지 않음 |
