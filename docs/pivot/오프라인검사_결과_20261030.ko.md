## 검사한 6개 구역

요청한 목록 그대로 나눴다.

### 1 · 준비 상태

- `phase` 가 `ACTIVE_LOCAL_TEST` 가 아니면 `signIn`·`addNetwork` 가 **지갑을
  건드리지 않고** 서버에도 보내지 않는다 (rpc 0회 · 요청 0회로 확인)
- 서버가 보낸 `NORMAL_HOST_NOT_ACTIVATED` · `BC_NORMAL_PROCEDURE_NOT_READY` 를
  `API_REQUEST_FAILED` 로 뭉개지 않고 코드 그대로 보존한다
- 두 역할 화면 모두 쓰기 버튼 5종(`바로 받기`·`서명 문구 받기`·`지갑으로
  서명하기`·`수령 결과 확인`·`결과 확인`)을 그리지 않는다. **`api` 가 있어도
  `phase` 가 막는다**

### 2 · 인증 취소·만료

- 만료된 `/auth/nonce` 문구에는 **서명 요청 자체를 보내지 않는다**
- 지갑 거절(4001)과 지갑 오류를 `BC_WALLET_REJECTED` · `BC_WALLET_FAILED` 로
  가른다. 거절은 실패가 아니라 선택이다
- **서명 창이 떠 있는 사이에 계정을 갈아타면 그 서명을 쓰지 않는다** —
  `/auth/verify` 로 보내지 않고 주소도 남기지 않는다
- 로그인 뒤 `accountsChanged`·`chainChanged`·`disconnect` 셋 다 세션을
  끝내고 **`/auth/logout` 으로 서버 세션까지 회수한다**
- 같은 주소를 EIP-55 대소문자로 다시 쏘는 경우는 끊지 않는다
- 서버가 세션을 반쪽만 주면(csrf 모양 불일치) 쓰지 않는다

### 3 · 조회 실패

- JSON 이 아닌 응답(404 본문·200 HTML·빈 본문)을 성공으로 읽지 않는다
- **5xx 쓰기는 `UNKNOWN`** 으로 적는다 — 실패로 단정하지 않고 자동
  재시도하지 않는다. 같은 조회는 `HTTP_ERROR` 다
- 허용 목록에 없는 서버 코드는 `BC_TRANSPORT_HTTP` 로 바꿔 서버 문자열이
  화면이나 오류 메시지로 새 나가지 않게 한다
- 본문 상한(성공 512KiB)에서 읽기를 멈춘다
- 중단(`BC_TRANSPORT_CANCELLED`)과 시간 초과(`BC_TRANSPORT_TIMEOUT`)를 가른다
- **조회가 실패해도 못 받은 값을 0으로 채우지 않는다**

### 4 · 오래된 판정

- 동의를 보내기 **직전에 판정을 다시 읽는다.** `targetDecisionId` 가
  바뀌었거나 **개정 번호만** 바뀌어도 보내지 않고, 안 보냈다고 적는다
- 대조군으로 "판정이 그대로면 보낸다" 를 같이 확인했다. 아무것도 안 하는
  버튼이라서 통과한 게 아니다
- 서버가 `BC_VIEW_STALE` · `BC_DECISION_TARGET` 로 답하면 다시 불러오라고 적는다
- `bothCurrent: false` 인데 기록이 있으면 **양쪽 확인이라고 적지 않는다**

### 5 · 조회와 클릭 충돌

- 보내는 중에는 버튼이 잠긴다. 동의가 두 번 나가지 않는다
- **결과를 모르면(`UNKNOWN`) 다시 보내기를 권하지 않는다.** 버튼이
  `결과 확인` 으로 바뀌고, 누르면 쓰기가 아니라 **같은 멱등 키로 조회**한다
- 이미 확인한 역할에는 버튼을 그리지 않는다

### 6 · 영수증 null / 성공

- 조회 경로가 없으면(`receiptHttpAvailable: false`) 버튼 대신 없다고 적는다
- 영수증이 `null` 을 주면 "아직 못 받은 값" 으로 적고 **0 으로 적지 않는다**
- `INCLUDED` 를 최종 확정으로 보이게 두지 않는다. `FINALIZED` 에는 그 경고가
  붙지 않고 수령액·정확 금액 확인이 뜬다
- 수락 뒤 판정이 바뀌어도 이미 받은 권리를 지우지 않는다

## 이 검사로 찾은 것 2건 — 둘 다 고쳤다

### (1) 오류 28종이 영어 코드로 그대로 노출됐다

`panels.js` 의 `ERROR_TEXT` 표에 없는 코드는 `errorText` 가 **코드 문자열을
그대로 화면에 적는다.** 조회 실패·인증 취소·만료가 **전부 이 표를 지나가므로**,
조금만 어긋나면 참가자가 이런 것을 봤다.

> BC_TRANSPORT_HTTP

빠져 있던 것이 28개였다. `BOOTCAMP_CODES` 전체와 지갑·transport 가 던지는
코드를 모두 덮었다. 표가 다시 비는 것을 막는 시험도 넣었다 — 코드가 하나
늘어날 때마다 영어가 새는 길이 하나 생기므로 기계로 막는다.

10-28 답변의 이 지적이 가리킨 자리와 같다.

> "'경로 없음' 은 개발 진단으로, 참가자 화면은 쉬운 말로"

### (2) 학생 화면이 준비 상태를 말하지 않았다

`phase` 가 `PREPARED_NOT_ACTIVATED` 일 때 **운영자 화면은 막힌 이유를 적고
있었는데 학생 화면은 아무 말도 하지 않았다.** 쓰기 버튼은 제대로 막혀 있어서
겉보기엔 정상이었지만, 히어로가 합성 fixture 숫자를 **자기 기록처럼** 띄웠다.

> 조건 진행 중 · 1개 남았습니다

`heroLine` 에 `NOT_ACTIVE` 가지가 없었다. 로그인 전 상태를 막으려고 쓴
`SIGNED_OUT` 가지와 **같은 종류의 오해**인데 그 자리가 비어 있었다. 더 나쁜 건
히어로 `sub` 가 `NOT_ACTIVE` 에서 막힌 이유를 **일부러 지우고 있었다는 점**이다 —
히어로가 말할 거라고 보고 지웠는데, 정작 말하는 자리가 없었다.

가지를 넣었다. 아래 숫자가 아직 자기 것이 아니라고 적는다.

> 준비 중 · 아직 열리지 않았어요
> 서버가 아직 켜지지 않았어요. 내 기록을 불러오지 못했으니 아래 숫자는 아직
> 내 것이 아닙니다. 열리면 바로 확인하실 수 있어요.
