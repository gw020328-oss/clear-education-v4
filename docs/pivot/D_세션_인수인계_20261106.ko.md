## 0. 꼭 지킬 것 (사용자가 여러 번 강조)

- **커밋·푸시·PR·답글은 각각 사용자에게 물어 승인받은 뒤에만.** 단, 사용자가 "한큐에 다 하고 보내자" 라고 한 범위 안에서는 커밋까지는 진행하고 푸시 전에 한 번 묻는다.
- **단계마다 화면을 먼저 띄워 보여주고 "다음에 뭘 할까요" 를 묻는다.** 혼자 몰아서 끝내지 않는다. 어느 화면(운영자/참가자/Moodle)인지부터, 쉬운 말로.
- **봉인 파일 금지**(백엔드 sha256 핀): `web/styles.css`, `web/src/main.js`, `web/src/bootcamp/{connect,criteria,live-dashboard,live-evidence,operator-view,recipient-panel,review-window,student-view,team-application,team-entry,team-render}.js`. 새 파일 + 봉인 안 된 파일로만 작업하고, 봉인 파일에는 통합 담당이 "마운트 한 줄" 만 넣는다.
- 대시보드(index.html 쪽) 문구는 **합니다체**. `web/tools/verify-screens.mjs` 가 해요체 서술문(어요/예요/에요)을 잡는다. Moodle 탭 카드 페이지(condition-cards.html)는 해요체를 쓴다.
- 값을 지어내지 않는다. 없는 서버 값은 "서버가 아직 주지 않은 값". 접수(QUEUED)만으로 충족·확정 표시 금지. 지급 완료는 `acceptedRight && claimState==='FINALIZED' && receivedAtoms!=null` 일 때만.
- 푸시 전 `node tools/check-public-content.mjs` (저장소 루트, 5~8분). 캡처 같은 이진 파일은 본 PR 가지에 넣지 않는다(검사에 BINARY_REQUIRES_REVIEW 로 뜸).
- 대본(발표 스크립트)은 사용자가 요청하기 전엔 묻지 않는다.
