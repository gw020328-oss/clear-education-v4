| 메서드 | 무엇 | 언제 생겼나 |
|---|---|---|

## 내가 가정했던 것과 다른 점

### 1. 수령 계정 등록 — 이름도 서명 방식도 다르다

| | 내가 가정 | 실제 |
|---|---|---|
| 메서드 | `api.registerRecipient(app)` | `recipientRegistration` + `submitRecipientRegistration` |
| 서명 | `personal_sign` (문구 한 줄) | **`eth_signTypedData_v4`** (EIP-712 구조화 데이터) |
| 단계 | 한 번 | GET 으로 요청 받기 → 서명 → POST 로 제출 |

등록 payload 에 참가자·수령인·신청 ID·정책/매핑 해시·chainId·
verifyingContract·salt·nonce·deadline 이 들어 있다. `types` 에
`EIP712Domain` 을 프론트가 직접 넣어야 한다.

`status` 는 `NOT_READY` / `AWAITING_SIGNATURE` / `SIGNED` / `STALE` / `EXPIRED`,
체인 쪽은 별도로 `chainStatus` 가 `NOT_OBSERVED` / `NOT_REGISTERED` /
`INCLUDED`. **`SIGNED` 를 등록 완료로 표시하면 안 된다.**

지금 우리 온보딩의 「수령 계정 등록하기」는 시연용 가짜다. 실제 경로가
생겼으므로 바꿀 수 있다.

### 2. 운영자 AI 승인 화면 — **아예 안 만들었다**

`POST /bootcamp/v4/applications/:app/reflection-approval`.
운영자가 **이번 AI 호출을 승인**해야 회고 판정이 돈다. 화면에 모델·외부
전송 여부·비용·호출 한도·남은 시간을 보여주고, 별도 확인 체크 + 직접
클릭으로만 승인한다.

`normal-client` 에 없어서 직접 호출해야 한다
(`tools/bootcamp/test-client/driver.js` 의 `approveAi` 가 기준).

**프론트 지침이 "반드시 연결해" 라고 적은 항목인데 빠져 있다.**

### 3. 오류 신고 — 여전히 **쓰기 경로가 없다**

`reviewChain(app)` 은 **조회**뿐이다. 접수(POST) 는 없다.
S4 문서도 "S3 쓰기는 변경하지 않는다" 라고 적는다.

→ 지금 화면이 "이 서버에는 오류 접수 경로가 아직 없습니다" 라고 쓰는 게
**지금도 맞다.** 라이브 월드의 신고·재검증은 우리가 정한 모델이고, 서버에
생기면 대조해야 한다.

### 4. 재검증(`revalidation`) 도 쓰기 경로 없음

같은 이유로 화면이 "재검증 요청 경로가 아직 없습니다" 로 두는 게 맞다.

## ⚠ 제일 큰 것 — 지갑 방식이 B안이 아니다

우리는 **B안(내장 지갑 — 구글 로그인만 하면 뒤에서 지갑 생성)** 으로 정해진
줄 알고 화면을 만들었다. 백엔드 저장소를 보면 **아니다.**

| 문서 | 날짜 | 적힌 말 |
|---|---|---|
| `docs/bootcamp-authority-review/FUNDING_RELAYER.ko.md:67` | 10-17 | "AA·**embedded wallet**·paymaster·session key·custody·외부 가입을 **도입하지 않는다**" |
| `docs/current/PYTHON_BOOTCAMP_R2.ko.md:71` | 10-18 | "서버 relayer가 native TEST 가스를 부담할 수 있어도 **지갑 생성/연결이 불필요해지는 것은 아니다** … 신규 AA/**embedded wallet**/paymaster/외부 가입/세션키/custodial key는 **도입하지 않는다**" |

그리고 그 뒤에 **실제로 짜인 코드**가 전부 브라우저 지갑 전제다.

- 로그인: SIWE (`/auth/nonce` → 지갑 메시지 서명 → `/auth/verify`)
- 수령인 등록(PR #115, 10-25): `eth_signTypedData_v4`
- 지갑 사건 처리: `accountsChanged` / `chainChanged` / `disconnect`
- 네트워크 전환: EIP-3085 (지갑에 체인 추가)
- 프론트 지침(10-27): "두 역할은 서로 다른 주소/브라우저 쿠키 저장소를 써"

전부 MetaMask 같은 **브라우저 확장 지갑**을 쓰는 사람의 이야기다.

오규원이 준 `CLEAR_MVP_통합기획서_내장지갑_가스대납_보완검토안`(10-23)이
B안을 제안했지만, **그 문서는 저장소에 없고** 그 뒤에 짜인 코드는 A안이다.
제안은 제안으로 남아 있고 구현은 A안으로 갔다고 보는 게 맞다.

### 우리 화면과 어긋나는 지점

- 온보딩 1단계가 「구글 계정으로 시작하기」인데, 실제로는 **「지갑 연결」**이다
- "따로 설치할 것은 없습니다" 라고 적혀 있는데, 실제로는 **MetaMask 설치 필요**
- "학생은 온체인 거래를 보내지 않습니다" 는 맞다 (relayer 가 가스 부담).
  그러나 **지갑은 있어야 한다**
- 발표 노트북 두 대에 각각 다른 주소의 지갑이 있어야 한다 (참가자/운영자)

### 물어볼 것

- **A안으로 확정인가.** 확정이면 온보딩 문구를 전부 지갑 기준으로 바꾼다
- B안으로 갈 거면 **누가 언제** 하나. 백엔드 로그인(SIWE)·서명 검증이 전부
  바뀌고, CSP 도 SDK 도메인으로 열어야 한다. 3주에 가능한가
- 발표 노트북에 MetaMask 를 깔아 두는 게 전제인가
