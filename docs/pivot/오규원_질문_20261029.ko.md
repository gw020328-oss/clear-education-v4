# 오규원에게 — 남은 질문 (2026-10-29)

10-28 답변으로 많이 풀렸다. 풀린 것과 남은 것을 가른다.
흩어져 있던 세 문서의 질문을 여기로 모았다.

## 먼저 알릴 것 — 지갑 결정이 바뀌었다

**팀이 오늘(10-29) 학생 지갑을 내장 지갑으로 확정했다.** 운영자는 브라우저
지갑(MetaMask) 그대로다. 목표를 내장으로 두자는 10-28 답변과 방향은 같지만,
**지금 화면을 내장 전제로 바꿨다**는 점이 다르다.

그래서 **학생은 실서버에 로그인할 수 없는 상태가 됐다** — SDK 가 없으니
provider 가 없다. 그대로 두면 활성화 뒤 통합 시험(신청 → 원천 → AI 승인 →
지급)을 학생 쪽에서 못 돌린다.

받은 답변대로 길을 따로 뒀다.

> "현재 경로로 먼저 통합을 검증하는 것과 내장 지갑 목표를 폐기하는 것은
> 다른 결정이야."

- 제품 경로는 내장 지갑뿐이다. 저절로 외부 지갑으로 떨어지지 않는다.
- 학생 온보딩 아래에 **「시험용 브라우저 지갑으로 연결」** 을 따로 뒀다.
  브라우저에 확장이 있을 때만 보이고, 사람이 눌러야 켜진다.
- 켜면 화면이 그렇게 적는다 — "시험용으로 브라우저 지갑에 연결했습니다.
  실제 서비스에서는 계정이 자동으로 만들어지며, 이 주소는 쓰이지 않습니다."

연결·서명은 `connect.js` / `wallet-session.js` 어댑터로 이미 분리돼 있다.
SDK 가 `window.clearWallet` 에 올라오면 그쪽을 먼저 집는다.

---

## A. 지갑·Reclaim — **제일 급함**

### A1. claim owner 로 내장 지갑 주소를 쓸 수 있나

`PYTHON_BOOTCAMP_P0.ko.md` 의 pair proof 가 두 증명을 **같은 signed
username·claim owner** 로 묶는다. claim owner 가 지갑 주소라면, SDK 가 만든
EOA 도 그 자리에 쓸 수 있나.

**안 되면 지갑 결정을 되돌려야 한다.** 그래서 SDK 공급자를 고르기 전에
이 답이 필요하다.

### A2. pair proof 가 구현됐나, 아직 설계인가

`PRODUCT_STORE.ko.md` 는 "원천/서명/계정 통제는 producer 책임이며 **현재
합성만 허용**" 이라고 적는다. P1 이 어디까지 됐나.

### A3. 공증 대상 두 페이지가 각각 어디인가

공개 인증서 페이지(`hackerrank.com/certificates/<12자리>`)는 **로그인 없이
열리고 이름만 보인다** — 날짜도 계정 식별자도 없다(직접 확인). dashboard 쪽
응답에는 무엇이 들어 있나.

### A4. 두 증명을 어떤 모양으로 주나

화면은 지금 조건 상세에 `① 계정 통제 증명` · `② 인증서 증명` · `두 증명
결합` 세 줄로 그린다. **값은 합성이다.** 서버 모양이 정해지면 그대로 바꾼다.

---

## B. 돈이 드나드는 길

### B1. 금고 주소를 화면이 어디서 받나

`normal-client.mjs` 에 예치·충전 쓰기 경로가 없고, `/__dev/config` 와
`session()` 어디에도 금고 주소가 없다. 그래서 **실서버에서는 운영자가
충전할 방법이 화면에 없다.**

지금은 "충전은 CLEAR 를 거치지 않습니다. 운영자 지갑에서 기수 금고로 직접
보내시면 … 이 서버는 아직 금고 주소를 알려주지 않아 여기서 거래를 만들어
드릴 수 없습니다" 라고 적어 뒀다.

주소를 `session()` 에 실어 주면 화면에서 지갑에 ERC-20 전송을 요청할 수
있다(서버 API 없이 된다). 그렇게 해도 되나, 아니면 주소만 보여주고 운영자가
직접 보내게 하나.

### B2. 학생이 받은 토큰의 전송 가스는 누가 내나

갓 만든 내장 지갑은 native 토큰이 0이라 **받고도 옮길 수 없다.**
`FUNDING_RELAYER.ko.md` 가 paymaster 를 배제하는데, 그게 **지급 거래에만**
해당하나 학생의 후속 전송까지인가.

### B3. 현금화 경로를 무엇으로 보나

팀은 **자동 지급을 포기하지 않기로 했다** — 체인이 실제로 돈을 옮기고,
학원이 계좌이체하는 방식으로 후퇴하지 않는다. 그러면 실제 서비스에서
학생이 받은 토큰을 어떻게 현금으로 바꾸나.

- 스테이블코인 → 거래소 → 원화 (학생이 거래소 가입. "지갑 몰라도 된다" 가 무너짐)
- 스테이블코인 → SDK 내장 오프램프 (지갑을 끝까지 안 보여줌. 수수료·한국 지원 확인 필요)

후자면 **SDK 고를 때 한국 오프램프 지원을 같이 봐야 한다.** 심사위원이
물어볼 항목이라 답을 맞춰 두고 싶다.

## C. 절차

### C1. 미해결 종료된 학생은 그 뒤 어떻게 하나

조건은 다 채웠는데 신고가 상한 안에 안 풀려 절차가 끝난 경우다. 재신청인가,
수동 지급인가, 그대로 끝인가. 어느 문서에도 없다. 화면은 지금 "다음 절차는
운영자에게 문의해 주세요" 라고만 적는다.

10-28 답변의 "접수, 처리 대기, 재검증 진행, 정정, 미해결 종료, 체인 반영
상태를 구분하여 인계" 에도 **종료 이후**는 없었다.

### C2. 서버가 원천을 주기적으로 다시 읽나

학생이 과제를 냈는데 Moodle 기록이 늦게 들어오는 경우. 주기가 있으면 화면이
"곧 다시 확인합니다" 라고 적을 수 있다. 안 읽으면 늦게 들어온 기록은
무엇으로 반영되나.
