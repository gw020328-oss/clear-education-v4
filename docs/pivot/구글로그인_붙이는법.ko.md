# 실제 구글 로그인 붙이기 — 서준형이 할 것

2026-10-28. 지금은 「구글 계정으로 시작하기」가 시연용 계정을 만든다.
진짜 구글 로그인(Google Identity Services)으로 바꾸려면 아래가 필요하다.

**프론트 코드는 1·2 가 끝나면 바로 붙인다.** 그 전에는 쓸 수 없는 코드라
미리 넣지 않았다.

---

## 1. Google Cloud 에서 클라이언트 ID 받기 (서준형, 10분)

### ① 프로젝트 만들기

1. <https://console.cloud.google.com> 접속 (hyewon2409@gmail.com 로그인)
2. 맨 위 프로젝트 선택 드롭다운 → **새 프로젝트**
3. 이름 `CLEAR` → **만들기**
4. 만들어지면 그 프로젝트가 선택됐는지 확인

### ② OAuth 동의 화면 설정

1. 왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면**
2. User Type **외부(External)** → 만들기
3. 채울 것은 셋뿐이다
   - 앱 이름: `CLEAR`
   - 사용자 지원 이메일: 본인 메일
   - 개발자 연락처 정보: 본인 메일
4. 범위(Scope)는 **추가하지 않는다.** 기본 `email` `profile` `openid` 면 된다 —
   민감한 범위가 아니라 구글 검수가 필요 없다
5. **테스트 사용자**에 발표에서 로그인할 계정을 전부 추가한다
   (게시하지 않으면 여기 있는 계정만 로그인된다. 팀원 + 시연용 계정)

### ③ 클라이언트 ID 만들기

1. **API 및 서비스 → 사용자 인증 정보** → **사용자 인증 정보 만들기** →
   **OAuth 클라이언트 ID**
2. 애플리케이션 유형: **웹 애플리케이션**
3. **승인된 JavaScript 원본**에 둘 다 넣는다

   ```
   http://localhost
   http://localhost:5500
   ```

   **127.0.0.1 은 넣지 않는다.** 구글 문서가 `http://localhost` 만 적는다.
   우리 개발 서버는 127.0.0.1 에 묶여 있지만 `http://localhost:5500` 으로도
   열린다(확인함). 그러니 **발표 때 주소창에 localhost 를 쓴다.**
4. 리디렉션 URI 는 비워 둔다. 버튼 방식은 리디렉션을 쓰지 않는다
5. **만들기** → 뜨는 **클라이언트 ID** 를 복사
   (`...apps.googleusercontent.com` 로 끝나는 긴 문자열)
   **클라이언트 보안 비밀번호는 쓰지 않는다** — 브라우저 코드에 넣으면 안 된다

### ④ 나한테 알려 줄 것

- 클라이언트 ID 문자열
- 발표에 쓸 주소 (`http://localhost:5500` 인지 다른 포트인지)

## 2. CSP 열기 (오규원과 상의, 한 줄)

`src/dev/server.mjs:45` 가 지금 이렇다.

```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:;
connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'
```

구글 라이브러리가 **스크립트·iframe·네트워크·스타일** 넷을 다 쓰므로 넷 다
열어야 한다. 구글 문서가 지정한 경로만 연다.

```
script-src  'self' https://accounts.google.com/gsi/client
frame-src   https://accounts.google.com/gsi/
connect-src 'self' https://accounts.google.com/gsi/
style-src   'self' https://accounts.google.com/gsi/style
```

`connect-src` 와 `frame-src` 는 개별 끝점(`/gsi/status` 등)이 아니라 **부모
경로 `/gsi/`** 로 연다 — 구글이 라이브러리를 갱신할 때 끊기지 않게 하려는
것이고, 구글 문서가 그렇게 하라고 적는다.

> 이건 **백엔드 파일**이다. 내가 임의로 못 고친다. 오규원에게 이 네 줄을
> 보내고, 실서버 CSP 에 넣을지 개발 서버에만 넣을지 정해야 한다.

`web/tools/dev-server.mjs`(프론트 미리보기 서버)에는 CSP 가 없어서 손댈 게
없다. 미리보기로만 시연한다면 2번은 건너뛸 수 있다.

---

## 3. 토큰 검증 (오규원)

구글이 돌려주는 것은 **ID 토큰(JWT)** 이다. 브라우저가 받은 토큰을 서버가
검증해야 로그인이 성립한다.

- 서버가 구글 공개키로 서명을 검증
- `aud` 가 우리 클라이언트 ID 인지
- `iss` 가 `accounts.google.com` 인지
- `exp` 가 안 지났는지
- 통과하면 그 `email`/`sub` 로 세션을 만든다

**3번 없이 1·2 만 하면 구글 계정 선택 창은 진짜로 뜨지만, 받은 토큰을 아무도
검증하지 않는다.** 화면만 진짜고 로그인은 여전히 장식이다. 발표에서
"실제 구글 로그인입니다" 라고 말하려면 3번까지 있어야 한다.

그리고 B안 내장 지갑에서는 **그 이메일이 지갑 주소와 묶여야** 의미가 있다 —
어느 SDK(Privy·Web3Auth 등)를 쓰느냐에 따라 구글 로그인을 그쪽이 가져간다.

---

## 순서 제안

**SDK 를 먼저 정하는 게 낫다.** 내장 지갑 SDK 를 고르면 그 SDK 가 구글
로그인을 자기 방식으로 띄운다. 지금 GIS 를 붙였다가 SDK 가 정해지면
버려질 수 있다.

```
내장 지갑 SDK 결정  →  그 SDK 의 구글 로그인을 붙인다   (권장)
SDK 가 늦어지면     →  GIS 를 먼저 붙여 화면만 진짜로   (1·2 만)
```

어느 쪽이든 1번(클라이언트 ID)은 미리 받아 두면 손해가 없다.

---

## 하지 않는 것

**구글 로그인 화면을 흉내 내지 않는다.** 진짜와 구분 안 되는 가짜 로그인
페이지는 피싱과 같은 물건이다. 발표용이라도 만들지 않는다. 붙인다면 진짜
GIS 를 붙이고, 아니면 지금처럼 **시연용이라고 분명한** 버튼을 쓴다.
